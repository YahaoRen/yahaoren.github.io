**Q：为什么要做并发控制？**

答：因为多个进程并发访问共享数据时，如果不加控制，会产生竞态条件——最终结果取决于进程执行的交错顺序，而这个顺序不可控，导致结果时对时错。

举个例子，两个进程各对共享变量 count 加一。count++ 在底层是读、改、写三步，如果一个进程读到值之后、还没写回就被打断，另一个进程也读到同样的旧值，两个各加一次最后只加成了一次，结果就错了。

所以要通过并发控制（互斥和同步）给共享数据的访问排好队：互斥保证同一时刻只有一个进程进临界区，同步保证进程间该有的先后顺序。目的就是让并发执行既不出错、又能协调配合。

并发是什么

**Q：并发是什么？**

答：并发是指宏观上多个程序在同一时间段内都在推进，但微观上它们是交替执行的——单个 CPU 某一时刻其实只在跑一个程序，只是切换得很快，看起来像同时进行。

要和并行区分开：并行是微观上真的同时执行，必须有多核才行；并发单核就能做到。

并发和共享是操作系统最基本的两个特征，互为存在条件，没有并发和共享就谈不上虚拟和异步。


# 第 1 周：概述 + 进程与线程

## 一、操作系统概述

### Q1. 操作系统是干什么的？★

**答：** 操作系统有三重身份：

1. **资源的管理者**：管理处理机、内存、文件、设备四类资源。
2. **向上提供接口**：给用户提供命令接口和 GUI，给程序员提供程序接口（系统调用）。
3. **对硬件的扩展与抽象**：在裸机上包一层，把"磁道扇区"抽象成"文件"，把物理内存抽象成"每个进程独占的地址空间"。这一层叫虚拟机。

> 核心手艺是"抽象"：把复杂、易错、需竞争的硬件细节藏起来，给上层一个干净、独占、好用的假象。

**四大特征：** 并发、共享、虚拟、异步。

- **并发**：宏观同时、微观交替（区别于**并行**——并行是真的同时，需多核）。
- **共享**：资源被多进程共同使用（互斥共享 / 同时共享）。
- **虚拟**：一个物理实体变成多个逻辑实体（时分复用、空分复用）。
- **异步**：进程走走停停，推进速度不可预知。
- **关系**：并发和共享是最基本的两个特征，互为存在条件；没有它俩就谈不上虚拟和异步。

### Q2. 为什么要区分内核态和用户态？两态怎么切换？★★

**答：** 如果所有程序都能执行"停机""修改页表""操作 I/O"这类危险指令，一个用户程序就能搞垮整台机器。所以 CPU 把指令分为**特权指令**和**非特权指令**，用 PSW 里的标志位标记当前是内核态还是用户态。用户态执行特权指令，CPU 直接抛异常拦下。

**切换方向（高频考点）：**

- **用户态 → 内核态**：只能通过**中断/异常**，硬件自动完成，属于**被动**。
- **内核态 → 用户态**：执行一条特权指令修改 PSW 标志位，操作系统**主动**让出。

### Q3. 中断和异常的区别？系统调用属于哪一类？★

**答：** 中断是操作系统**夺回 CPU 控制权的唯一手段**。

- **内中断（异常）**：来自 CPU 内部，和当前指令有关。
    - 陷入（trap）：自愿中断，执行 trap 指令——**系统调用走这条路**。
    - 故障（fault）：可修复，如缺页、除零，处理后可能重新执行原指令。
    - 终止（abort）：不可修复，进程被杀。
- **外中断（中断）**：来自 CPU 外部，和当前指令无关。如**时钟中断**、I/O 完成中断。

> **系统调用属于内中断（陷入 trap）。** **时钟中断**是分时系统能"轮转"的物理基础——没有它，死循环进程永不还 CPU。

### Q4. 系统调用和库函数有什么区别？举例。★★

**答：** 关键区别是**是否动用了操作系统管理的资源**。

- **纯库函数**：只在用户态做计算，不进内核。如 `strlen`、`abs`。
- **封装了系统调用的库函数**：底层要动用硬件/资源，必须陷入内核。如 `printf`（底层调 `write`）、`malloc`（底层可能调 `brk`/`mmap`）。

**系统调用流程：** 参数放进寄存器 → 执行 trap 指令 → 触发内中断切内核态 → 系统调用入口程序查系统调用表 → 执行内核服务 → 返回用户态。

> 补充：`printf` 有用户态缓冲区，攒够了才真正陷入内核——这解释了 fork 后 printf 输出重复的现象。

### Q5. 大内核和微内核的区别？★

**答：** 这是"性能 vs 可靠性"的权衡。

- **大内核（宏内核）**：进程/内存/设备/文件管理全放内核态。模块间直接调用，**性能高**；但内核庞大、一处崩全崩、可维护性差。Linux、Windows 属此类。
- **微内核**：内核只留最基本的（进程通信、地址空间、基本调度），其他服务放用户态当普通进程。**可靠、易扩展**；但服务间通信要反复切换态，**性能差**。

> 微内核的开销本质是**态切换次数变多了**。

## 二、进程

### Q6. 程序和进程有什么区别？★

**答：** 用"菜谱 vs 做菜"打比方：

- **程序**是躺在磁盘上的静态代码（菜谱）。
- **进程**是程序跑起来的动态过程（正在下厨）。
- 同一份程序可以跑出多个进程（同一菜谱在两个灶上各炒一份）。

> 进程的关键词：**动态的、正在执行的过程**。

### Q7. 为什么说 PCB 是进程存在的唯一标志？★★

**答：** 操作系统要同时管几百个进程，靠给每个进程建一张"户口本"记录它的全部信息，这就是 **PCB（进程控制块）**。操作系统眼里没有"进程"这个东西，只看得见一张张 PCB：**创建进程 = 建 PCB，撤销进程 = 删 PCB**。所以 PCB 是进程存在的唯一标志。

**PCB 记什么：** PID、处理机现场（PC、寄存器）、调度信息（状态、优先级）、资源清单（打开的文件、占用的内存）。

**进程的组成：** PCB + 程序段 + 数据段。后两者合称进程实体（进程映像）。

> 进程是动态的，进程实体（映像）是静态的。

### Q8. 画进程状态转换图，解释为什么没有"阻塞→运行"。★★

**五状态：**

- **运行态**：CPU 正在执行它（单核同一时刻只有一个）。
- **就绪态**：万事俱备，只差 CPU。
- **阻塞态**：在等某事件（如 I/O），给它 CPU 也没用。
- **创建态**：正在被建立。
- **终止态**：正在做善后。

**四条关键转换：**

| 转换      | 触发           | 主动/被动       |
| ------- | ------------ | ----------- |
| 就绪 → 运行 | 被调度选中，分到 CPU | —           |
| 运行 → 就绪 | 时间片用完 / 被抢占  | —           |
| 运行 → 阻塞 | 主动请求资源、等 I/O | **主动**      |
| 阻塞 → 就绪 | 等待的事件发生      | **被动（被唤醒）** |

**三个坑（必答）：**

1. **没有"阻塞→运行"**：唤醒后只能进就绪态，重新排队等 CPU，不能直接抢回。
2. **没有"就绪→阻塞"**：就绪态没在 CPU 上跑，不可能"执行到一半缺资源"。
3. **运行→阻塞是主动，阻塞→就绪是被动**：一个自己喊停，一个被别人叫醒。

### Q9. 什么是原语？为什么必须不可中断？靠什么实现？★

**答：** 原语是一段**不可被中断**、要么全做完要么不做的操作。进程控制（创建、撤销、阻塞、唤醒）都靠原语完成。

- **为什么不可中断**：它在改 PCB 和系统数据结构，改到一半被打断数据会乱套。
- **靠什么实现**：**关中断**——把中断一关，这段操作就没人能插进来。

> **阻塞原语和唤醒原语必须成对出现**，否则被阻塞的进程永远醒不过来（死锁来源之一）。

## 三、进程通信

### Q10. 为什么需要进程通信？三种方式各是什么？★

**答：** 每个进程有独立地址空间，彼此看不见对方数据（操作系统故意的，防止互相乱写）。但有时进程确实需要交换数据（如 `ps | grep`），所以需要进程通信。三种方式：

|方式|比方|速度|谁管秩序|特点|
|---|---|---|---|---|
|**共享存储**|公用储物间|**最快**|进程自己（需配互斥）|直接读写共享内存|
|**消息传递**|寄快递|较慢|操作系统|send/receive，省心|
|**管道**|单向水管|中等|操作系统（满/空自动阻塞）|半双工、FIFO、自带同步|

- **共享存储**：操作系统划一块共享内存映射到两进程地址空间，直接读写。最快，但要自己配互斥防撞车。
- **消息传递**：数据封装成消息，用 send/receive 收发。分直接通信（点对点）和间接通信（通过信箱）。省心但有搬运开销。
- **管道**：内核里一个固定大小的缓冲区。**半双工（单向）、FIFO、写满则阻塞写端、读空则阻塞读端**。

### Q11. 管道的"满/空阻塞"为什么是天然同步？★

**答：** 管道写满了写进程就得等，读空了读进程就得等。这逼着快的一方等慢的一方，双方自动配上节奏——所以是一种天然的同步机制。

> 主线：越"直接读写内存"越快但越要自己操心秩序；越"交给操作系统代办"越省心但有搬运开销。这是 OS 反复出现的"性能 vs 省心"权衡。

## 四、线程

### Q12. 进程和线程有什么区别？★★（复试必问，能说 4 点以上，每点带"为什么"）

**本质一句话：进程是"资源分配"的单位，线程是"CPU 调度"的单位。**

- 进程负责占资源（房子），线程负责上 CPU 跑（房子里的人）。

**六点区别：**

|#|维度|区别|记忆|
|---|---|---|---|
|1|**调度**|线程是调度基本单位，进程是资源分配基本单位|上 CPU 的是线程，占资源的是进程|
|2|**资源**|进程有独立资源；线程几乎不占资源，共享所属进程资源|房子是进程的，人几乎空手|
|3|**地址空间**|进程间地址空间独立互不可见；同进程内线程共享地址空间|进程各住各家，线程同住一屋|
|4|**通信**|进程间要靠 IPC；线程直接读写共享变量|线程递东西伸手就拿|
|5|**切换开销**|进程切换要换地址空间（换页表）开销大；同进程内线程切换不用换，开销小|换人上班 vs 换一整户搬家|
|6|**健壮性**|一个进程崩不影响别的进程；同进程内一个线程崩可能拖垮整个进程|各家独立，同屋连坐|

### Q13. 为什么线程切换比进程切换开销小？★★

**答：** 同一进程内的线程**共享地址空间**，切换时**不用切换页表、不用刷新 TLB**；而进程切换要整个换掉地址空间，代价大得多。

> 一句话：线程切换不用换地址空间，所以更轻量。

### Q14. 线程共享什么、私有什么？为什么栈必须私有？★

- **共享（属于整个进程）**：内存地址空间（代码段、数据段、堆）、打开的文件、其他资源。
- **私有（属于每个线程）**：程序计数器 PC、寄存器、**栈**。
- **为什么栈必须私有**：若两线程共用一个栈，各自的函数调用、局部变量会压在一起分不清谁是谁。

> 每个线程有自己的 TCB（线程控制块），记录 PC、寄存器、栈。

### Q15. 用户级线程和内核级线程的区别？用户级线程一个阻塞会怎样？★

- **用户级线程（ULT）**：由用户程序里的线程库自己管，OS 不知道其存在。切换快（不进内核）；但**一个线程系统调用阻塞，OS 以为整个进程卡住，把整个进程挂起**，且**无法利用多核**。
- **内核级线程（KLT）**：OS 直接管理每个线程。一个阻塞可调度同进程其他线程，能真正多核并行；但管理要进内核，开销大。

> 又是"性能 vs 功能"的权衡。

## 五、处理机调度

### Q16. 高、中、低级调度分别管什么？★

- **高级调度（作业调度）**：决定磁盘上的作业哪个调入内存、创建进程。频率最低。（进不进内存）
- **中级调度（内存调度）**：内存不够时把进程换出到磁盘（挂起），需要时换回。（换不换出去）
- **低级调度（进程调度）**：从就绪队列挑进程给 CPU。频率最高。（下一个上 CPU 是谁）

### Q17. 抢占式和非抢占式的区别？★

- **非抢占式**：进程拿到 CPU 就跑到自己主动让出（跑完或等 I/O），别人不能打断。
- **抢占式**：来了"更该服务"的进程，OS 可强行收回 CPU。（如时间片轮转、SRTN）

### Q18. 各调度算法的思路和优缺点？★

|算法|抢占?|最大优点|最大毛病|
|---|---|---|---|
|**FCFS** 先来先服务|非抢占|公平、简单|对短任务不友好|
|**SJF** 短作业优先|有抢占版(SRTN)|平均周转时间最短|长任务饿死、需预知运行时间|
|**优先级**|两种都有|灵活分轻重|低优先级饿死（用老化 aging 解决）|
|**时间片轮转 RR**|抢占|公平、响应快|时间片大小难拿捏|
|**多级反馈队列**|抢占|兼顾长短任务、不需预知|实现复杂|

**评价指标：**

- **周转时间 = 完成时间 − 到达时间**（总共花多久）。
- **带权周转时间 = 周转时间 ÷ 运行时间**（等得冤不冤，越接近 1 越好）。

### Q19. 时间片轮转，时间片太大/太小分别会怎样？★

- **太大** → 退化成 FCFS（大到每个进程一次跑完）。
- **太小** → 频繁切换，切换开销占大头，真正干活时间少。
- **要适中**：让大部分交互任务在一两个时间片内完成，又不至于切换太频繁。

### Q20. 多级反馈队列为什么能兼顾长短任务、还不用预知运行时间？★★

**答：** 设多个优先级递减、时间片递增的队列：

1. 新进程进最高优先级队列，按时间片轮转。
2. 一个时间片没跑完 → 降到下一级（享受更长时间片、更低优先级）。
3. 只有上层队列空了才轮到下层。
4. 等待过久可上提，防饥饿。

**妙处：**

- **短任务**在前几级就跑完 → 照顾短任务（有 SJF 的味道）。
- **长任务**逐级下沉，分到大时间片，一旦轮到能一口气跑很久 → 照顾长任务。
- 靠"跑不完就下沉"**自动识别长任务**，解决了 SJF"必须预知运行时间"的硬伤。

# 第 2 周：同步互斥 + 死锁

> **主线：** 共享数据并发访问会出**竞态** → 用**互斥**上锁 → 还要**同步**协调先后 → 组装成三大经典问题 → 协调不当会**死锁** → 破坏死锁条件来防治。

## 六、同步互斥基础

### Q21. 用 count++ 讲：为什么两进程各加一次结果可能不是 2？根子在哪？★

**答：** `count++` 在 CPU 眼里是三步：**读**（读到内存值）→ **改**（寄存器加 1）→ **写**（写回内存）。进程随时可能被时钟中断打断换成另一进程。若发生这种交错：

|时刻|A|B|count|
|---|---|---|---|
|1|读到 0||0|
|2|(被打断)|读到 0|0|
|3||加1写回1|1|
|4|加1写回1||1|

各加一次本该是 2，结果是 1。这就是**竞态条件**：结果取决于不可控的执行交错。**根子在于 `count++` 做到一半被打断了。**

**术语：**

- **临界资源**：一次只允许一个进程使用的资源。
- **临界区**：访问临界资源的那段代码。
- **互斥**：一个进程在临界区时，别的进程不许进入访问同一资源的临界区。

### Q22. 互斥的四条原则是什么？重点解释"让权等待"。★

用"单人厕所"记：

1. **空闲让进**：没人时想进的能立刻进。
2. **忙则等待**：有人时其他人在外面等（互斥本身）。
3. **有限等待**：等的人在有限时间内能轮到（防饿死）。
4. **让权等待**：进不去就**释放 CPU**去干别的/睡觉，而不是站门口空转。

**让权等待重点：** 反对**忙等（自旋）**——反复看牌子白白占 CPU。要求进不去就主动阻塞、让出 CPU，等能进了再被唤醒。（接进程阻塞态 + 调度）

**互斥实现思路演进：** 软件方法（皮特森等，多为忙等）→ 硬件方法（关中断、TestAndSet/Swap 原子指令，多为忙等）→ **信号量**（能满足让权等待）。

- **关中断的问题**：只对单核有效；把关中断交给用户程序太危险（不打开就系统废了），只适合内核短暂用。

## 七、信号量

### Q23. P 操作和 V 操作分别做什么？★★

**信号量 = 一个整数 S + 一个等待队列。** S 的含义：**正数=剩余可用资源数，负数=正在排队等待的进程数**。

**P 操作（申请资源，Passeren）：**

```
P(S):
    S = S - 1;              // 我要占一个
    if (S < 0) 阻塞自己;     // 没资源了 → 去睡觉（让权等待）
```

**V 操作（释放资源，Verhogen）：**

```
V(S):
    S = S + 1;              // 我还一个
    if (S <= 0) 唤醒一个;   // 还有人在等 → 叫醒一个
```

- **P 里"先减再判负"**：减完的负值恰好记录有几个进程在等。
- **V 里"≤0 才唤醒"**：加 1 后仍 ≤0 说明之前 S 是负的、有人在睡。
- P、V 必须是**原子操作**（否则自身出竞态）。

### Q24. 信号量实现互斥和同步，在初值和 P/V 位置上有什么根本区别？★★

||互斥|同步|
|---|---|---|
|解决什么|一次只让一个进程进|强制操作先后顺序（A 先 B 后）|
|信号量初值|**1**|通常 **0**|
|P/V 位置|**同一进程内**成对（P 临界区 V）|**分在两个进程**|
|口诀|临界区前 P、后 V|**前 V 后 P**（先做的进程 V，后做的进程 P）|

**互斥套路：**

```
mutex = 1;
P(mutex);  临界区;  V(mutex);
```

**同步套路（A 生产、B 打印）：**

```
S = 0;
进程A: 生产; V(S);      进程B: P(S); 打印;
```

- 无论谁先跑，都保证"A 生产在前、B 打印在后"。
- **反直觉点：V(S) 在 A 里，P(S) 在 B 里，不在同一进程！**
- 口诀：**谁先做谁在后面 V，谁后做谁在前面 P**，同步信号量初值设 0。

## 八、三大经典问题

### Q25. 生产者-消费者：信号量初值？为什么 P(empty) 必须在 P(mutex) 前？★★

**三个信号量：**

|信号量|含义|初值|
|---|---|---|
|`empty`|缓冲区空位数|**N**|
|`full`|缓冲区已用数（产品数）|**0**|
|`mutex`|保护缓冲区的互斥锁|**1**|

> empty + full 恒等于 N。

**代码：**

```
生产者:                          消费者:
生产产品;                         P(full);      // 申请一个产品
P(empty);   // 申请一个空位        P(mutex);     // 上锁
P(mutex);   // 上锁               取出产品;
放入缓冲区;                        V(mutex);     // 解锁
V(mutex);   // 解锁               V(empty);     // 释放一个空位
V(full);    // 通知有产品了         消费产品;
```

**为什么 P(empty) 必须在 P(mutex) 前（★★死锁陷阱）：** 若颠倒成先 P(mutex) 后 P(empty)：假设缓冲区满，生产者先拿到锁，再 P(empty) 发现没空位就**抱着锁去睡觉**；消费者想取产品却拿不到锁，也睡了。生产者等消费者取货腾空位，消费者等生产者放锁——**互相等待，永久死锁**。

**结论：两个 P 操作中，互斥信号量的 P 必须放最内层（最后做）；把互斥 P 提前会"抱锁睡眠"导致死锁。**

### Q26. 为什么两个 V 操作顺序无所谓？★

**答：** V 操作只做"加1/可能唤醒"，**永远不会让进程阻塞**（V 里没有睡觉那一步）。既然不会阻塞，就不存在"抱锁睡眠"风险，顺序自由。

> 记忆：**P 可能睡眠，顺序要命；V 不会睡眠，顺序自由。**

**追问：**

- mutex 能省吗？**不能**。empty/full 只保证资源够不够，不保证两人不同时操作缓冲区。
- 多生产者多消费者成立吗？**成立**。

### Q27. 读者-写者：核心设计和缺陷？★

**三条规则：** 读-读可并发；读-写互斥；写-写互斥。（**允许多读者同时读，但写者必须独占**）

**核心设计：**

- 信号量 `rw=1`（写者独占访问权）、`mutex=1`（保护 count）、计数器 `count`（当前读者数）。
- **第一个读者** P(rw) 把门锁给读者阵营（挡住写者）；**最后一个读者** V(rw) 把门还给写者。中间读者直接读。
- 改 count 要用 mutex 包住（count 也是共享变量）；但"读文档"不放进 mutex（否则读者不能并发）。

**缺陷：** 这是"读者优先"版本，读者源源不断则 count 不归零，**写者饿死**。

### Q28. 哲学家进餐：为什么会死锁？怎么破解？★

**死锁场景：** 五哲学家各拿左筷子，都想拿右筷子（已是邻座左筷），**人人占一根、人人等一根，形成环，永久卡死**。

**三种破法：**

1. **限最多 4 人同时上桌**（初值 4 的信号量）：5 根筷子给 4 人抢，至少 1 人能拿到两根。
2. **奇偶反序**：奇数号先左后右、偶数号先右后左，破坏整齐的环。
3. **要么全拿要么不拿**：给拿筷子动作整体加锁，检查两根都空才拿。

## 九、死锁

### Q29. 死锁的定义？和饥饿、死循环的区别？★

**死锁：** 多个进程各占一些资源、又都等待对方占有的资源，导致全部永久阻塞的僵局。（关键词：互相等待、各自占着不放、永久）

||死锁|饥饿|死循环|
|---|---|---|---|
|是什么|一组进程互相等待全卡死|某进程长期得不到资源|逻辑错误一直转圈|
|进程数|至少两个|可能一个|一个|
|根源|资源循环等待|分配不公平|代码 bug|
|状态|都在**阻塞**态|阻塞/就绪|**运行**态（空转）|

> 死锁 vs 饥饿关键：死锁是一群进程互等都动不了；饥饿是某进程排不上队但系统整体正常运转。

### Q30. 死锁的四个必要条件？用哲学家问题逐条举例。★★

口诀："**互请不循**"——必须**同时满足**，破坏任一即可防止死锁。

1. **互斥条件**：资源一次只能被一个进程占用。→ 一根筷子同时只能一人拿。
2. **请求并保持**：占有至少一个资源，又请求新资源，请求被阻塞时**对已有资源不放**。→ 拿着左筷子请求右筷子、拿不到也不放左筷子。
3. **不可剥夺**：进程占有的资源用完前不能被强行抢走。→ 不能把哲学家手里的筷子硬抢走。
4. **循环等待**：存在进程-资源的**环形等待链**。→ 0等1、1等2……4等0，绕成一圈。

> "必要条件"含义：死锁发生时四个一定都满足；破坏任一，死锁不可能发生。（必要不充分：四个都满足也不一定马上死锁，但死锁必然四个都在）

### Q31. 死锁的四种处理策略？严格程度怎么排？★

由严到松：

|策略|时机|做法|代价|
|---|---|---|---|
|**预防**|事前|破坏四条件之一|限制死板，利用率低|
|**避免**|事中|分配前判断是否安全（银行家）|需预知需求，开销大|
|**检测与解除**|事后|允许发生，检测再解开|检测/解除有开销|
|**鸵鸟策略**|不管|假装看不见，死了重启|简单，真死锁很惨|

> 现实系统（Linux/Windows）大多用鸵鸟策略——严格预防/避免代价太高，桌面死锁概率低。

### Q32. 死锁预防的四种破坏办法？为什么互斥破坏不了？★

- **破坏互斥**：基本做不到，互斥是资源固有物理属性（打印机没法两人同时用）。
- **破坏请求并保持**：一次性申请全部资源。代价：利用率极低、可能饥饿。
- **破坏不可剥夺**：得不到新资源就释放已占有的。代价：实现复杂、开销大、工作可能作废。
- **破坏循环等待**：资源有序分配法——给资源编号，必须按编号递增顺序申请。**最实用**。

### Q33. 什么是安全状态？不安全一定死锁吗？银行家算法核心思想？★★

- **安全状态**：能找到一个**安全序列**，按它分配能让每个进程都拿到所需资源、跑完、归还，全部不死锁。
- **不安全状态**：找不到这样的序列。**不安全 ≠ 一定死锁**，只是有风险；但避免策略绝不让系统进入不安全状态。

**银行家算法比方：** 银行家（OS）放贷前盘算"这笔钱借出去后，还能不能满足所有客户最大需求、让他们逐个还钱"，能才借，保证不破产（不死锁）。

**四张表：**

- **Available**：当前还剩多少资源。
- **Max**：每个进程最多要多少。
- **Allocation**：每个进程已拿多少。
- **Need = Max − Allocation**：还差多少。

**安全性检查思路（讲，不用手算）：**

1. Work = Available，所有进程标记未完成。
2. 找一个 **Need ≤ Work** 的未完成进程。
3. 假设它跑完并归还：**Work = Work + Allocation**，标记完成。
4. 重复，直到所有进程完成（→ 安全，得到安全序列）或卡住（→ 不安全）。

**处理请求时：** 先检查 Request ≤ Need 且 ≤ Available → 试探性分配 → 跑安全性检查 → 安全则真分配，不安全则撤销让其等待。

### Q34. 死锁检测与解除？★

- **检测**：维护资源分配图，反复消去能被满足的进程的边，消不掉的就是死锁进程（本质也是"找环"/"看能否找到顺序让大家跑完"）。
- **解除**：① 资源剥夺（抢资源给别人）；② 撤销进程（杀掉死锁进程）；③ 进程回退（退到之前的检查点重来）。

# 第 3 周：内存管理

> **主线：** 程序里的地址是"假的"(逻辑地址) → 翻译成"真的"(物理地址) → 怎么翻译？分页/分段 → 内存装不下大程序 → 虚拟内存：只装用到的，缺了去调 → 内存满了 → 页面置换决定换谁出去。

## 十、内存基础与地址转换

### Q35. 为什么需要区分逻辑地址和物理地址？★

**答：** 程序编译时根本不知道将来会被装到内存的哪个位置（今天装 1000 开始、明天可能 5000 开始）。所以：

- **逻辑地址（虚拟地址）**：程序里用的地址，**从 0 开始编号**，编译器假设程序独占内存。是"假的""相对的"。
- **物理地址**：内存条上真实的位置。是"真的"。

**比方：** 逻辑地址像"楼里 3 楼 2 号房"（相对这栋楼），物理地址像这套房子在城市里的经纬度坐标。同一条指令装到内存不同位置，楼内门牌号（逻辑地址）不变，城市坐标（物理地址）会变。

> 为什么非要分两层：编译时算不出物理地址，只能先用逻辑地址占位，运行装入时再翻译。

### Q36. 什么是地址重定位？动态重定位好在哪？★

**答：** 逻辑地址 → 物理地址的翻译过程叫**地址重定位**，有三种时机：

- **绝对装入**：编译时直接用物理地址。只适合单道、位置固定，现在基本不用。
- **静态重定位**：装入内存那一刻一次性把逻辑地址全改成物理地址。缺点：**装入后不能再移动**。
- **动态重定位（现代方式★）**：装入时不改逻辑地址，**真正访问某地址的瞬间**由硬件（重定位寄存器/基址寄存器）当场翻译：物理地址 = 基址 + 逻辑地址。

**动态重定位好处（高频追问）：** 因为翻译是"访问时才做"，程序可以在内存里**被搬来搬去**（换位置只需更新基址寄存器），为虚拟内存的换进换出打下基础。

### Q37. 内存管理主要负责哪几件事？★

1. **地址翻译**：逻辑地址 → 物理地址。
2. **内存分配与回收**：程序来了给内存，走了收回。
3. **内存保护**：进程 A 不能访问进程 B 的内存。靠**上下限寄存器**（规定进程只能访问某地址范围，越界报错）。
4. **内存扩充**：内存不够时用虚拟内存，让程序感觉内存比实际大。

## 十一、连续分配与碎片

### Q38. 连续分配有哪几种？★

**连续分配 = 给每个进程分配一块连续的内存空间。**

- **单一连续分配**：内存分系统区和用户区，用户区只放一道程序。简单但只能单道，利用率低。
- **固定分区分配**：把用户区预先划成若干**固定大小**的分区，每区放一道程序。会产生**内部碎片**。
- **动态分区分配**：不预先划分，进程来了**按需**分配一块连续空间。会产生**外部碎片**。

### Q39. 内部碎片和外部碎片的区别？★★（易混必问）

- **内部碎片**：分配给进程的空间**内部有用不完的浪费**。出现在**固定分区**——分区大小固定，进程用不满就剩一块。
- **外部碎片**：内存中存在**很多小的空闲块**，它们总和够大，但**不连续**，装不下一个需要连续空间的进程。出现在**动态分区**。

**记忆：内部碎片是"分给你了你没用完"，外部碎片是"空闲块太零碎凑不到一起"。**

**解决外部碎片：** **紧凑（拼凑/compaction）**——把内存中的进程都往一端挪，把零散空闲块合并成一大块。前提是支持动态重定位（能移动进程）。

### Q40. 动态分区的分配算法有哪几种？★

从空闲分区里挑哪一块给进程：

- **首次适应（First Fit）**：地址从低到高，找到第一个够大的就分。**综合性能最好**，低地址容易留下小碎片。
- **最佳适应（Best Fit）**：找**能满足的最小**那块。会留下越来越多**极小的**外部碎片，性能其实不好。
- **最坏适应（Worst Fit）**：找**最大**那块。缺点是很快没有大块可用。
- **邻近适应（Next Fit）**：从上次找到的位置继续找，让空闲块分布更均匀，但会使高地址大块也被用掉。

## 十二、分页

### Q41. 分页的基本思想是什么？★★

**答：** 连续分配有外部碎片问题（进程要连续空间）。分页的思路是：**不要求连续**。

- 把**逻辑地址空间**切成大小相等的**页（page）**。
- 把**物理内存**切成同样大小的**页框/物理块（frame）**。
- 进程的每一页可以**离散地**装到任意空闲页框里，不必连续。

这样就**消灭了外部碎片**（任何空闲页框都能用）。只剩下一点**内部碎片**（进程最后一页可能装不满一个页框）。

**页表（page table）：** 记录"进程的第几页 → 装在哪个物理页框"的映射表。每个进程一张页表，页表项记录页框号。

### Q42. 一个逻辑地址怎么翻译成物理地址？★★

**逻辑地址结构 = 页号 + 页内偏移。**（高位是页号，低位是页内偏移）

**翻译流程：**

1. 由逻辑地址算出**页号**和**页内偏移**（页号 = 逻辑地址 / 页大小，偏移 = 逻辑地址 % 页大小；实际是按二进制高低位直接拆分）。
2. 拿页号去**页表**里查，得到对应的**物理页框号**。
3. **物理地址 = 物理页框号 × 页大小 + 页内偏移**。

**关键点：页内偏移直接照搬，不用变**（页和页框一样大，页内位置不变），只需要把"页号"换成"页框号"。

**页表寄存器（PTR）：** 存放当前进程页表的**起始地址**和**长度**。进程切换时换 PTR，就切到了另一个进程的页表。

### Q43. 为什么需要多级页表？★

**答：** 单级页表太大，装不下。举例：32 位地址、页大小 4KB，则有 2²⁰ ≈ 100 万个页，每个页表项 4 字节，页表就要 **4MB 连续内存**。每个进程都要这么一大块连续空间，装不下也浪费（很多页根本没用到）。

**多级页表的解法：** 给页表**再做一次分页**——把大页表拆成一个个小页表（每个小页表刚好一页大），再用一张"页目录"（顶级页表）索引这些小页表。

**两个好处：**

1. **不需要一大块连续内存**存整张页表（拆成小块离散存放）。
2. **按需装载**——没用到的那部分小页表**根本不用建/不用调入内存**，省空间。

**代价（高频追问）：** 访存次数变多。二级页表要查两次页表（先查页目录、再查小页表）**再加一次访问真正数据**，共 **3 次访存**。这就是下面 TLB 要解决的问题。

### Q44. TLB（快表）是什么？为什么能加速？★★

**答：** 多级页表访存次数多（每次访问数据前要先多次查页表），慢。**TLB（快表，Translation Lookaside Buffer）** 是一个**高速缓存**，存放**最近用过的页表项**（页号 → 页框号）。

- 访问一个逻辑地址时，先查 TLB：
    - **命中（TLB hit）**：直接拿到页框号，**省掉查内存页表的步骤**，快。
    - **未命中（TLB miss）**：再去内存查页表，查到后把这项也放进 TLB。
- TLB 有效的原因是**程序的局部性**（下面 Q46）——短时间内反复访问同一批页，TLB 命中率很高（通常 90%+）。

> 记忆：TLB 是"页表的缓存"，把慢的"查内存页表"变成快的"查片上缓存"。TLB 在 CPU 内部（MMU 里），比内存快得多。

## 十三、分段与段页式

### Q45. 分段是什么？分页和分段有什么区别？★

**分段：** 按程序的**逻辑结构**划分——代码段、数据段、栈段等，每段长度不等，段内连续。逻辑地址 = **段号 + 段内偏移**，靠**段表**（记录每段的基址和长度）翻译。

**分页 vs 分段（★易混必问）：**

||分页|分段|
|---|---|---|
|划分依据|物理，大小**固定**|逻辑，大小**可变**|
|目的|提高内存利用率、消除外部碎片|满足用户/程序的逻辑需求（模块化、共享、保护）|
|对用户|透明（用户不感知页）|用户可见（用户按段组织程序）|
|地址|一维（一个逻辑地址）|二维（段号 + 段内偏移）|
|碎片|有内部碎片，无外部碎片|有外部碎片，无内部碎片|
|共享保护|不便|**方便**（按段共享/保护，如共享一个代码段）|

**段页式：** 先把程序**分段**（满足逻辑需求），每段再**分页**（满足内存管理）。逻辑地址 = **段号 + 页号 + 页内偏移**。先查段表找到该段的页表，再查页表找页框。综合了两者优点，但访存更多。

## 十四、虚拟内存

### Q46. 什么是局部性原理？★★（虚拟内存的理论基础）

**答：** 程序执行有局部性：

- **时间局部性**：现在访问的指令/数据，**不久后很可能再次访问**（如循环体、被反复用的变量）。
- **空间局部性**：现在访问了某地址，**附近的地址很快也会被访问**（如数组顺序遍历、指令顺序执行）。

**意义：** 因为有局部性，程序在一段时间内只集中访问一小部分页。**所以没必要把整个程序全装进内存**——只装当前用到的那部分就行。这是虚拟内存和 TLB 都能奏效的根本原因。

### Q47. 什么是虚拟内存？★★

**答：** 基于局部性原理：**程序运行时，只把当前需要的部分装入内存，其余留在磁盘上；用到没装入的部分时，再从磁盘调入；内存不够就把暂时不用的换出到磁盘。** 这样用户感觉到的内存容量远大于实际物理内存，这个"看起来很大"的内存就是虚拟内存。

**三个特征：**

- **多次性**：一个程序可分多次调入内存。
- **对换性**：运行时可换进换出。
- **虚拟性**：逻辑上扩充了内存容量。

**实现方式：** 请求分页 / 请求分段 / 请求段页式（最常见是**请求分页**）。

### Q48. 缺页中断的完整流程是什么？★★（本章最高频，务必背熟）

**背景：** 请求分页里，页表项要加几个标志位：**有效位（存在位）**——标记这一页是否在内存中；还有**修改位（脏位）、访问位**等。

**流程：**

1. CPU 访问某逻辑地址，查页表，发现该页**有效位=0**（不在内存）→ 触发**缺页中断（fault，可恢复的内中断）**。
2. 缺页中断处理程序接管，去磁盘找到这一页。
3. **看内存有没有空闲页框：**
    - 有空闲页框 → 直接把该页调入。
    - **没有空闲页框 → 用页面置换算法选一页换出**（若被换出的页被修改过——修改位=1——要先写回磁盘；没改过则直接丢弃）。
4. 把需要的页从磁盘调入空闲页框。
5. **修改页表**：填上页框号、把有效位置 1。
6. **重新执行**被中断的那条指令（这次就能访问到了）。

**追问点：**

- 缺页中断属于**内中断里的故障（fault）**，是**可恢复的**，处理完回到原指令**重新执行**（区别于 abort）。
- 缺页**不一定**要淘汰页面（有空闲页框就不用）。
- 一条指令执行期间可能**多次缺页**（如指令跨页、操作数跨页）。

### Q49. 什么是抖动（颠簸）？怎么解决？★

**答：** **抖动（Thrashing）**：刚换出去的页面马上又要用、又换进来，进程大部分时间都花在换进换出上，几乎不干正事，性能急剧下降。

**原因：** 同时运行的进程太多，分给每个进程的物理页框太少，装不下它当前需要的那批页。

**解决——工作集（Working Set）：** 工作集是进程在某段时间内**实际访问的页面集合**（近期活跃的页）。系统给进程分配的页框数应**不少于其工作集大小**，保证它常用的页都在内存。据此控制多道程序度（进程太多就少放几个），避免抖动。

## 十五、页面置换算法

> 复试要求：讲清**思路**和**优劣**，不要求手算缺页次数。

### Q50. 有哪些页面置换算法？各自思路和优劣？★★

**目标：内存满了、要换一页出去，换哪一页？换出去的最好是"以后最久不用的"。**

**1. 最佳置换算法（OPT / Optimal）**

- 思路：换出**未来最长时间内不会被访问**的页。
- 缺页率**最低**，是理论最优。
- **无法实现**（要预知未来），只作为衡量其他算法好坏的标尺。

**2. 先进先出（FIFO）**

- 思路：换出**最早进入内存**的页（像排队，先进先出）。
- 简单，但性能差——最早进来的页可能是常用页。
- **会出现 Belady 异常★**：**分配的页框数增多，缺页反而增多**。（反直觉，是 FIFO 独有的缺陷）

**3. 最近最久未使用（LRU / Least Recently Used）**

- 思路：换出**最近最久没被访问**的页（过去最久没用的，将来大概也最久不用——基于局部性）。
- 性能**接近 OPT**，是实际效果最好的算法之一。
- **不会有 Belady 异常**（它是"栈算法"）。
- 缺点：**实现开销大**，需要硬件记录每页最近访问时间/维护访问顺序。

**4. 时钟算法（CLOCK / 二次机会 / NRU）**

- 思路：LRU 的低开销近似。给每页一个**访问位**，页面组成一个环形队列，一个指针像时钟一样转：
    - 指针指到的页，访问位=1 → 给"第二次机会"，把访问位清 0，指针继续走。
    - 访问位=0 → 换出它。
- 用较小的代价逼近 LRU 的效果，是实际系统常用的。
- **改进型时钟算法**：同时看**访问位和修改位**（访问位, 修改位）。优先淘汰 (0,0)（没访问没修改，最理想），其次 (0,1)……**尽量避免淘汰被修改过的页**（那样要写回磁盘，多一次 I/O）。

**四种对比一句话：** OPT 最优但不可实现 → LRU 效果接近 OPT 但开销大 → CLOCK 用访问位低成本近似 LRU → FIFO 最简单但差、还有 Belady 异常。

### Q51. 页面分配/置换策略？★

- **固定分配 vs 可变分配**：给进程的页框数**是否固定**。
- **局部置换 vs 全局置换**：缺页时**只能换自己的页** vs **可以换别的进程的页**。
- 常见组合：
    - **固定分配局部置换**：页框数固定，只换自己的。简单但不灵活。
    - **可变分配全局置换**：缺页就从空闲页框拿，没有就换某个进程的页。灵活，最常用。
    - **可变分配局部置换**：根据缺页率动态调整每个进程的页框数，只换自己的。

> **调入时机：** 预调页（提前调入预计要用的页，靠局部性预测）+ 请求调页（用到才调）。

> **主线：** 文件是"字节的抽象"→ 用户看到的是逻辑结构和目录 → 底层要把文件存到磁盘（物理结构）→ 磁盘怎么高效读写（磁盘调度）→ 数据怎么在设备和内存间搬（I/O 控制方式）。

## 十六、文件系统基础

### Q52. 什么是文件？文件的逻辑结构有哪些？★

**文件：** 操作系统对**磁盘存储**的抽象——把"磁道、扇区"这些物理细节藏起来，给用户一个"有名字、可读写的字节序列/记录序列"。（回想 Day 1，这就是 OS 的"抽象"手艺）

**文件逻辑结构（用户眼中文件的组织方式）：**

- **顺序文件**：记录一个接一个存。顺序访问快，随机访问慢。
- **索引文件**：为记录建**索引表**（关键字 → 记录位置），可快速随机访问（尤其变长记录）。
- **索引顺序文件**：折中——记录分组，为每组建一条索引。查找先查索引定位到组，再组内顺序找。

> 注意区分：**逻辑结构**是"用户怎么看文件"，**物理结构**（Q57）是"文件怎么存到磁盘"，两者独立。

## 十七、目录与 inode

### Q53. 目录是什么？FCB 和 inode 是什么？★

**目录：** 用来**组织和查找文件**的结构。目录里存的是一条条**文件控制块（FCB）**，记录文件的名字、属性、以及**存在磁盘哪里**等信息。查找文件 = 在目录里按文件名找到对应 FCB。

**目录结构演进：**

- 单级目录：全系统一张目录，不能重名。
- 两级目录：每个用户一张目录，解决了不同用户重名。
- **树形目录**：多级目录，现代系统用的（文件夹套文件夹）。
- 无环图目录：允许**共享**（一个文件挂在多个目录下）。

### Q54. inode 是什么？为什么要把文件名和文件信息分开？★

**答：** 在 Unix/Linux 里，把 FCB 拆成两部分：

- **目录项**只存**文件名 + inode 号**（很小）。
- **inode（索引节点）**存文件的**其余全部信息**：属性（大小、权限、时间戳）、以及**数据块的物理地址（索引）**。

**为什么这样拆（高频追问）：** 查找文件时只需要按文件名扫目录，**目录项越小，一个磁盘块能装的目录项越多，查找越快**（读一次磁盘块能比较更多文件名）。把庞大的物理地址信息挪到 inode，用到时才读 inode。

### Q55. 硬链接和软链接的区别？★

- **硬链接**：多个**目录项指向同一个 inode**（同一个文件多个名字）。删除一个名字，只要还有别的硬链接指着，文件就不删（inode 里有**链接计数**，减到 0 才真删）。不能跨文件系统、不能链接目录。
- **软链接（符号链接）**：是一个**特殊文件，内容是另一个文件的路径**（像快捷方式）。原文件删了，软链接就**失效（悬空）**。可跨文件系统、可链接目录。

> 记忆：硬链接指向 inode（是"同一个文件的别名"），软链接指向路径（是"一个记着路的小文件"）。

## 十八、文件物理结构

### Q56. 文件的物理结构（磁盘分配方式）有哪几种？★★（本章重点）

**问题：一个文件的数据要存到磁盘的若干块上，怎么记录"这个文件用了哪些块"？** 三种方式：

**1. 连续分配**

- 文件占**连续的**磁盘块。目录里记**起始块号 + 长度**。
- 优点：**顺序访问快**（连续读，磁头几乎不用动）；支持随机访问（起始块 + 偏移直接算出）。
- 缺点：**有外部碎片**；文件**难以增长**（后面块可能被占了）。

**2. 链接分配（离散）**

- 文件的块**离散**存放，每块留一个指针指向下一块，串成链。
    - **隐式链接**：指针藏在每个数据块里。**只能顺序访问**（要读第 i 块必须从头顺着指针走），随机访问差；且一个指针坏了后面全断。
    - **显式链接（FAT）★**：把所有指针集中成一张**文件分配表（FAT）**放在内存。查下一块查 FAT 即可，**不用读磁盘就能随机定位**，可靠性也好。（FAT 文件系统由此得名）
- 优点：**无外部碎片，文件易增长**（加一块接到链尾即可）。

**3. 索引分配★**

- 给每个文件建一个**索引块**，里面按顺序存该文件所有数据块的块号（一张目录：第 0 块在哪、第 1 块在哪……）。
- 优点：**支持高效随机访问**（查索引块直接定位任意块）；文件易增长。
- 缺点：索引块本身占空间；**文件很大时一个索引块装不下所有块号** → 用**多级索引 / 混合索引**解决。

**inode 用的就是混合索引★：** inode 里放若干**直接指针**（直接指向数据块，小文件够用）+ **一级间接指针**（指向一个索引块）+ **二级间接指针**（指向"指向索引块的索引块"）+ **三级间接**。**小文件用直接指针快速访问，大文件靠多级间接扩展容量**——兼顾了大小文件。

**三种对比：** 连续分配快但难增长有碎片；链接分配易增长但（隐式）随机访问差；索引分配随机访问好、易增长，是现代主流。

## 十九、空闲空间管理与文件系统层次

### Q57. 磁盘空闲块怎么管理？★

要记录磁盘上**哪些块是空闲的**，常见方法：

- **位示图（bitmap）**：用一个二进制位表示一个块，0=空闲、1=已用。简单，找连续空闲块方便。
- **空闲链表法**：把空闲块串成链表。
- **成组链接法**：Unix 用的，结合了空闲表和空闲链表的优点，适合大文件系统。

### Q58. 文件系统的层次结构？（了解即可）

从上到下大致：用户接口 → 逻辑文件系统（管目录、FCB）→ 文件组织模块（逻辑块 → 物理块的映射，即物理结构）→ 基本文件系统（发出读写块的命令）→ I/O 控制（设备驱动）→ 物理设备。

> 一句话：**上层管"文件是什么、在哪个目录"，下层管"数据块具体在磁盘哪、怎么读写"。**

## 二十、磁盘结构与磁盘调度

### Q59. 磁盘的物理结构？访问时间由哪几部分组成？★

**结构：** 磁盘由多个**盘面**组成，每面有很多同心圆**磁道（track）**，每条磁道分成若干**扇区（sector，最小读写单位）**；所有盘面上相同半径的磁道组成一个**柱面（cylinder）**。

**磁盘访问时间 = 寻道时间 + 旋转延迟 + 传输时间：**

- **寻道时间**：磁头移动到目标磁道的时间。**最大、最值得优化**——磁盘调度算法就是为了减少它。
- **旋转延迟**：等待目标扇区转到磁头下方的时间（平均转半圈）。
- **传输时间**：读写数据本身的时间。

### Q60. 磁盘调度算法有哪些？各自思路和优劣？★★（本章重点，讲思路即可）

**目标：一堆访问请求分布在不同磁道，怎么安排读取顺序，让磁头总移动距离（寻道）最短？**

- **FCFS（先来先服务）**：按请求到达顺序。公平简单，但磁头可能来回乱跑，效率低。
- **SSTF（最短寻道时间优先）**：每次选**离当前磁头最近**的请求。寻道短，但**可能饿死**——远处的请求一直被近处的插队。
- **SCAN（电梯算法）★**：磁头**朝一个方向移动**，沿途处理请求，到头再折返。像电梯。不会饿死。缺点：刚经过的磁道要等磁头折返回来才服务，**边缘磁道等待久、中间磁道被照顾多**。
- **C-SCAN（循环扫描）**：磁头到一端后**直接快速返回起点**（返回途中不处理请求），再朝同方向扫。让各磁道等待更**均匀**。
- **LOOK / C-LOOK**：SCAN/C-SCAN 的改进——磁头**不必走到磁盘最边缘**，走到该方向最远的请求处就折返。省掉无谓移动。

**一句话对比：** FCFS 公平但低效；SSTF 快但会饿死；SCAN/C-SCAN（电梯类）兼顾效率和公平，是主流；LOOK 系列进一步省掉到边缘的空跑。

## 二十一、I/O 管理

### Q61. I/O 控制方式有哪几种？逐步演进解决了什么？★★（本章最高频）

**核心问题：数据在设备和内存之间怎么传？CPU 参与多少？** 四种方式，一步步"解放 CPU"：

**1. 程序直接控制（轮询 / 忙等）**

- CPU 不停**查询**设备状态（"好了吗？好了吗？"），直到设备就绪才传数据。
- 缺点：**CPU 一直空转等 I/O**，浪费严重。

**2. 中断驱动方式**

- CPU 发起 I/O 后**去干别的**，设备完成时**发中断**通知 CPU 来处理。
- 进步：CPU 不用忙等了。
- 缺点：**每传一个字（数据）就中断一次**，数据量大时中断太频繁，CPU 频繁被打断。

**3. DMA（直接存储器访问）★**

- 增设 **DMA 控制器**，让**设备和内存直接成块传数据**，不经过 CPU。
- CPU 只在**传输开始时**发命令、**整块传完后**收一次中断。
- 进步：**以"块"为单位传输**，一整块只中断一次，大大减少 CPU 干预。适合磁盘等块设备。

**4. 通道方式**

- 通道是一个**弱化的、专管 I/O 的处理器**，能执行一组通道指令（通道程序）。
- CPU 只需向通道发一条指令，通道就能**自动完成一批 I/O 操作**（多个块、多个设备），完成后才中断 CPU。
- 进步：比 DMA 更进一步，CPU 干预最少。

**一句话演进：** 轮询（CPU 忙等）→ 中断（CPU 不等了，但每字一中断）→ DMA（成块传，每块一中断）→ 通道（一批操作才中断）。**每一步都在减少 CPU 对 I/O 的干预。**

### Q62. I/O 软件的层次结构？★

从上到下：

1. **用户层软件**：提供库函数（如 printf）给用户调用。
2. **设备独立性软件**：与设备无关的通用功能（命名、保护、缓冲、分配、错误处理），给上层统一接口。
3. **设备驱动程序**：与硬件打交道，把上层抽象命令翻译成具体设备的操作。
4. **中断处理程序**：I/O 完成时处理中断。

> **设备独立性**：用户程序用**逻辑设备名**请求 I/O，不用管具体是哪台物理设备，由系统映射。好处：程序不依赖具体设备，可移植、易替换。

### Q63. 为什么要设缓冲区？★

**答：** **缓解 CPU 和 I/O 设备速度不匹配的矛盾**（CPU 快、设备慢）；减少 I/O 中断频率；提高 CPU 和设备的**并行性**。

- **单缓冲**：一个缓冲区，装数据和取数据不能同时。
- **双缓冲**：两个缓冲区交替，一个在装、另一个在取，并行度更高。
- **循环缓冲 / 缓冲池**：多个缓冲区循环使用/共享，供多个进程和设备用。

### Q64. 什么是 SPOOLing（假脱机）？★

**答：** **SPOOLing 技术把独占设备改造成共享设备。** 典型例子是打印机：

- 打印机是独占设备，一次只能一个进程用。若直接分配，进程占着它却时用时不用，利用率低。
- SPOOLing 的做法：在磁盘上开**输出井**，进程要打印时，数据**先高速写到磁盘输出井里**（进程立刻就"打印完"返回，不用真的等打印机），再由一个"打印守护进程"排队慢慢把井里的数据送去打印机。
- 效果：多个进程感觉自己**各自独占**了一台打印机（其实共享一台），设备利用率和进程效率都提高了。

> 本质：**用磁盘（快、可共享）做缓冲，把慢速独占设备虚拟成多个可共享的逻辑设备**——又是"虚拟"和"抽象"思想的应用。
