## 指令集架构
# 指令集架构（ISA）

## 📌大白话

**ISA 就是 CPU 和软件之间的 “约定手册”**。 软件（汇编、编译器）按照这本手册规定的指令格式写程序，CPU 照着手册识别、执行指令。

> 好比：遥控器（软件）和空调（CPU）要约定按键代表什么：按 1 是开机、按 2 调温度，这套按键规则就是指令集架构。

## 📌考试简答版（直接背）

**指令集架构 ISA：是计算机硬件与软件之间的接口，定义了 CPU 能够识别、执行的全部机器指令集合。** 它规定：

1. 有哪些指令（加减、跳转、访存等）
2. 指令格式：操作码、地址码怎么编排
3. 寄存器数量、长度
4. 内存寻址方式
5. 数据类型

软件只需要遵守 ISA 写代码；CPU 只要实现这套 ISA，就能跑对应软件。

## 📌两大经典分类

1. **CISC 复杂指令集（x86）**

- 代表：Intel、AMD 电脑 CPU
- 指令数量多、指令长短不一样；既有简单指令，也有很复杂指令，想让软件少干活。

2. **RISC 精简指令集（ARM、RISC‑V）**

- 代表：手机、平板、树莓派、RISC‑V 芯片
- 只保留最常用简单指令；**所有指令长度统一**；复杂功能靠多条简单指令拼出来。

## 📌关键考点（面试 / 选择题）

> ISA 属于**软硬件交界面**

- 软件视角：ISA 是 CPU 能看懂的全部命令
- 硬件视角：CPU 电路必须实现 ISA 里规定的每一条指令
**2. 问：指令集里有哪些寻址方式？（点到即止）**

- 记住最常见的3个就行：**立即数寻址**（常数直接给）、**寄存器寻址**（速度最快）、**偏移寻址**（基址+偏移，访问结构体数组常用）。如果问“哪种最快”，答**寄存器寻址**。
    
**3. 问：特权指令是什么？（保研必挖坑）**

- 答：操作系统内核才能用的指令（比如控制中断、改内存映射）。咱们写的普通APP只能用**用户态指令**。一旦用户程序想用特权指令，CPU会直接抛异常（缺页/非法操作），这就是操作系统保护机制的核心。

# CPU的工作流

**CPU 干活就是一个不停重复的循环：取指令、看懂它、执行、存结果。** 具体说，CPU 里有个叫 PC 的寄存器，专门记着下一条指令在内存的哪个位置。第一步**取指令**，按 PC 给的地址去内存把指令拿回来，放进指令寄存器，同时 PC 自动往后挪一格，指向下一条。第二步**译码**，把这条指令拆开看，前面一段是操作码，告诉 CPU 要干什么，后面是地址码，告诉它数在哪。第三步**取操作数**，按地址码把要算的数找出来，可能在寄存器里，也可能得去内存取。第四步**执行**，交给运算器 ALU 真正算，加减乘除或者比较大小。第五步**写回**，把结果存进寄存器或者内存。这一条干完，CPU 会**顺便看一眼有没有中断请求**，没有就回到第一步接着取下一条指令，有就先去处理中断。这么一圈一圈转下去，程序就跑起来了。

**如果老师追问"那 CPU 是一条一条串着干的吗"**，就接这句：早期是这样，但太浪费——取指令的时候运算器闲着，运算的时候取指部件闲着。所以现在用**流水线**，把这五步拆开重叠起来：第一条指令在译码的时候，第二条已经在取指了，就像洗衣服时第一件在烘干、第二件已经下水了。这样单条指令花的时间没变，但单位时间里完成的指令变多了。




## Q1. Cache 和主存之间有哪几种映射方式？★★★

**【一句话】** 直接映射是"一个萝卜一个坑"，全相联是"随便坐"，组相联是"先分组，组内随便坐"。

**【说人话】** 想象 Cache 是一个只有 8 个座位的小教室，主存是有 1000 个学生的大楼。学生要进教室，坐哪儿？

- **直接映射**：学号除以 8 取余数，余几就坐第几个座位。规矩死，但找人极快——你说学号我立刻知道该去哪个座位看。问题是学号 3 和学号 11 的两个人都只能坐 3 号位，哪怕其他 7 个座位全空着，他俩也得互相挤下去。
- **全相联映射**：随便坐哪儿都行。座位利用率最高，但找人时得挨个座位看一遍，成本高。
- **组相联映射**：8 个座位分成 4 组、每组 2 个。先按学号取余定组，进了组以后两个座位随便坐。找人只要看那一组的 2 个座位。**这是实际 CPU 用的方案**。

**【面试就这么说】** "有三种。直接映射是把主存块号对 Cache 行数取模，每个主存块只能放在固定的一行，好处是查找快、只需要一个比较器，坏处是冲突多，Cache 还有空位也可能被迫替换。全相联映射是主存块可以放在任意一行，命中率最高，但要把所有行的标记同时比一遍，硬件开销大。组相联是前两者的折中——**组间用直接映射决定放哪一组，组内用全相联可以放任意一行**，比如四路组相联就是每组四行、只要四个比较器。实际 CPU 基本都用组相联，因为它在命中率和硬件成本之间平衡得最好。"

> **老师可能追问："那相联度是不是越高越好？"** "不是。提高相联度确实能减少冲突缺失，但比较器变多会增加命中时间，功耗也上去了。而且收益是递减的——从直接映射提到二路的提升很明显，从八路提到十六路就几乎没提升了。所以主流是四路到八路。"

## Q2. Cache 的写策略有哪些？★★★

**【一句话】** 写直通 = 改了立刻同步到主存；写回 = 先记个账，等这块被赶走时再一次性写回去。

**【说人话】** 你在草稿纸（Cache）上改了一个数，正式账本（主存）要不要马上跟着改？

- **写直通**：每改一次就同步改账本。账本永远是对的，但每次都要跑一趟，慢。
- **写回**：只改草稿纸，在这页纸角上打个勾（叫**脏位**），表示"这页和账本不一样了"。等这页纸要被扔掉的时候，才去更新账本。快，但中途账本里的数是过期的。

还有一个小问题：如果要写的数**根本不在 Cache 里**怎么办？

- **写分配**：先把它从主存搬进 Cache 再写（想着后面可能还要写附近的数）→ 通常配写回
- **非写分配**：直接改主存，不搬 → 通常配写直通

**【面试就这么说】** "分命中和不命中两种情况。命中时，写直通是同时更新 Cache 和主存，一致性好但访存开销大，通常会加一个写缓冲来缓解；写回是只更新 Cache 并把这一行的脏位置一，等这行被替换出去时才写回主存，写的性能高但一致性维护复杂。不命中时，写分配会先把这块调入 Cache 再写，能利用空间局部性，一般和写回搭配；非写分配就直接写主存，一般和写直通搭配。多核情况下因为每个核有自己的 Cache，还要靠缓存一致性协议保证正确，最常见的是 MESI，用修改、独占、共享、无效四个状态标记缓存行。"

## Q3. 为什么 Cache 能起作用？局部性原理是什么？★★★

**【一句话】** 程序访问内存不是均匀撒网，而是扎堆的——刚用过的还会用，用了这个还会用旁边的。

**【说人话】** 这个是整个存储体系的**地基**，老师特别爱问，因为它能看出你是背的还是懂的。

- **时间局部性**：刚访问过的东西，很快还会再访问。典型是循环里的计数器 `i`，一个循环跑一万次，`i` 就被访问一万次。
- **空间局部性**：访问了某个地址，它旁边的地址马上也要用。典型是数组遍历 `a[0], a[1], a[2]...`，地址是连着的。

正因为程序有这个特点，把"最近用过的 + 它旁边的"那一小撮数据放进又快又小的 Cache 里，就能覆盖绝大部分访问。否则 Cache 再快也没用——如果程序完全随机访问内存，Cache 命中率就跟碰运气一样低。

**【面试就这么说】** "局部性原理分两种：时间局部性是指最近被访问的数据很可能马上被再次访问，比如循环里的循环变量；空间局部性是指访问了某个地址后，它邻近的地址很可能马上被访问，比如数组的顺序遍历。整个存储层次结构成立的前提就是局部性——正因为程序的访问是**集中而不是均匀分散**的，所以用一个小容量的高速缓存装下最近用的那一小部分，就能让绝大多数访问都在高速层完成，从而用接近 Cache 的速度提供接近主存的容量。如果程序的访问完全随机，Cache 就基本失效了。"

> 💡 **可以接你自己的研究**：这一点在深度学习里很直观。矩阵乘法之所以要做分块（tiling），就是为了人为制造空间局部性，让一小块数据留在缓存里被反复用；FlashAttention 的核心思路也是把注意力计算分块，让中间结果尽量留在 GPU 的片上 SRAM 里，减少对 HBM 的往返读写——本质上就是在做 Cache 友好的优化。

## Q4. 流水线是什么？有哪些冒险？怎么解决？★★★

**【一句话】** 流水线不让单条指令变快，而是让"总产量"变高。三种冒险：抢资源、等数据、猜错路。

**【说人话】** 洗衣服的比喻最好用：洗、烘、叠三步。一个人一件件干，第一件洗完才开始第二件。流水线的做法是——第一件在烘的时候，第二件已经在洗了。**单件衣服该花多久还是多久，但单位时间洗完的衣服变多了。**

经典五级流水（记住这五个词就够）： **取指令 → 译码 → 执行 → 访存 → 写回**

三种冒险，用生活语言理解：

**① 结构冒险 = 抢东西** 两条指令同一时刻都要用存储器（一个要取指令，一个要取数据）。 👉 解决：把指令 Cache 和数据 Cache 分开，各用各的。

**② 数据冒险 = 等前面的结果** 第二条指令要用第一条算出来的数，可第一条还没写回去。 👉 主要解决办法叫 **数据转发（也叫旁路）**：第一条在"执行"阶段已经把结果算出来了，别等它慢慢写回寄存器，直接从电路上抄近道送给第二条用。 👉 但有一种情况转发也救不了：第一条是从内存**取数**（load），数据要到"访存"阶段才拿到手，而第二条马上就要用。这时候只能**停一拍**，插一个空泡。这个叫 **load-use 冒险**，是最经典的追问点。

**③ 控制冒险 = 岔路口不知道走哪边** 遇到 if 判断，还没算出条件呢，下一条指令该取哪儿的？ 👉 解决：**分支预测**。先猜一条路走着，猜对了白赚，猜错了把已经走的清空重来。现代 CPU 的预测准确率能到 95% 以上。

**【面试就这么说】** "流水线是把一条指令的执行拆成若干阶段，让多条指令的不同阶段在时间上重叠，经典的五级是取指、译码、执行、访存、写回。要强调一点：**流水线并不缩短单条指令的执行时间**，因为加了流水寄存器反而略有增加，它提高的是吞吐率。

冒险有三种。结构冒险是多条指令抢同一个硬件资源，比如取指和访存都要用存储器，解决办法是把指令 Cache 和数据 Cache 分开。数据冒险是后面的指令要用前面还没写回的结果，主要靠**数据转发**，把结果从执行或访存阶段直接送到需要它的指令输入端；但如果前一条是 load 指令、后一条紧接着用它的结果，转发也来不及，必须停顿一个周期，也可以让编译器把无关指令调度过来填这个空。控制冒险是遇到分支指令时不知道下一条该取哪儿，靠分支预测解决，也可以把转移条件的判断提前到译码阶段来减少损失。"

> **追问："流水线级数是不是越多越好？"** "不是。加深流水线能提高主频，但代价有三个：一是分支预测失败时要清空的流水级更多，惩罚变大；二是流水寄存器本身的延迟和功耗占比上升；三是相关引起的停顿更频繁。Intel 早期的 NetBurst 架构做到三十多级之后性能反而不理想，后来退回来了，现在主流是十四到二十级。"

## Q5. 中断和 DMA 有什么区别？★★★

**【一句话】** 中断是"每来一件事都要打扰老板一次"；DMA 是"交代一声，你自己搬完了再告诉我"。

**【说人话】** CPU 是老板，外设是快递员，主存是仓库。

- **中断方式**：快递员每送到一个包裹，就敲门叫老板出来，老板亲手接过包裹放进仓库，再回去干活。包裹一多，老板一直被打断，什么正事都干不了。**关键点：数据要经过老板的手（CPU 寄存器）。**
- **DMA 方式**：老板一开始交代好"你把这一整车货放进仓库 3 号位"，然后就不管了。快递员**直接搬进仓库，不经过老板的手**。全部搬完之后，才敲一次门说"搬完了"。

由此推出四个区别（这四条是标准答案，建议成套背）：

||中断|DMA|
|---|---|---|
|数据走哪儿|要经过 CPU 寄存器|外设↔主存直连，不过 CPU|
|什么时候响应|**一条指令执行结束**后|**一个总线周期结束**后|
|谁优先|低|**高**（不及时处理会丢数据）|
|开销|要保护现场、跑服务程序|只借用总线，不保护现场|

**为什么响应时机不同？** 因为中断要打断程序去跑另一段代码，必须等当前指令做完一个完整动作才安全；而 DMA 只是**借一下总线**，CPU 的寄存器、程序状态都没动，所以随时可以插空，这个叫**周期窃取**。

**【面试就这么说】** "主要有四点区别。第一是数据通路：中断方式下数据要经过 CPU 的寄存器中转，DMA 是外设和主存之间的直接通路，不经过 CPU。第二是响应时机：中断要等**一条指令执行完**才响应，而 DMA 在**一个总线周期结束**时就能响应，因为 DMA 只是借用总线，不改变 CPU 的现场。第三是优先级：DMA 高于中断，因为外设的数据传输有实时性要求，不及时处理会丢数据。第四是开销：中断要保存和恢复现场、执行中断服务程序，本质是程序切换，开销大；DMA 不需要保护现场，只是让 CPU 让出一个总线周期，所以叫周期窃取。"

## Q6. 中断的处理过程是怎样的？★★★

**【一句话】** 关中断 → 保断点 → 找服务程序（这三步是硬件自动做的，叫中断隐指令）→ 保护现场 → 开中断 → 干活 → 关中断 → 恢复现场 → 返回。

**【说人话】** 就当成你正在写作业，突然有人敲门：

1. **先"闭耳"**（关中断）——处理这个人的时候别再让别人打断我，不然会乱。
2. **在作业本上夹个书签**（保存断点 PC 和状态字）——记住写到哪儿了。
3. **走到门口**（引出中断服务程序）。

以上三步是**硬件自动完成的**，速度快、不可分割，统称**中断隐指令**。注意它**不是一条真的指令**，你在指令手册里找不到它——这是很爱考的一个点。

4. **把桌上的笔、草稿都收进抽屉**（保护现场：保存通用寄存器）。
5. **重新"开耳"**（开中断）——现在可以允许更急的事再打断我了，这就是**中断嵌套**。
6. 处理这件事（执行中断服务程序）。
7. 处理完，再"闭耳"（关中断）——恢复现场的时候不能被打断，不然刚拿出来的笔又被人碰乱。
8. **把笔和草稿拿回桌上**（恢复现场）。
9. 开中断，**按书签接着写**（中断返回）。

**【面试就这么说】** "中断处理大致分五步。首先是**中断请求**，外设通过请求线向 CPU 发信号；然后是**中断判优**，多个请求同时来时按优先级排队；接着是**中断响应**，CPU 在一条指令执行结束时检查有没有请求，如果开着中断就响应，响应时执行**中断隐指令**——关中断、保存断点和程序状态字、引出中断服务程序，这三个动作由硬件自动完成，注意它不是指令系统里真实存在的一条指令；然后进入**中断服务程序**，先保护现场，再开中断以允许嵌套，执行具体服务，结束前关中断、恢复现场；最后**中断返回**，恢复断点和程序状态字，开中断，回到原程序继续执行。"

> **追问："服务程序里为什么要开中断？"** "为了允许更高优先级的中断打断当前的中断服务，也就是实现**多重中断（中断嵌套）**。如果全程关中断，就只能是单重中断，紧急事件得不到及时响应。"

> **追问："中断和异常有什么区别？"** "中断是**外部**事件引起的，跟当前执行的指令没关系，是异步的，比如键盘输入、定时器；异常是 CPU **内部**执行指令时产生的，一定和某条具体指令绑定，是同步的，比如除零、缺页、非法指令。异常又分三类：故障是可以恢复的、处理完重新执行这条指令，缺页就是典型；自陷是程序有意触发的，比如系统调用；终止是不可恢复的严重错误。"

## Q7. 虚拟内存怎么工作？TLB 是什么？★★★

**【一句话】** 虚拟内存让每个程序以为自己独占一大块连续内存；TLB 是"页表的 Cache"，为了不用每次都跑去内存查页表。

**【说人话】** 程序里写的地址（虚拟地址）是**假的**，真正的内存地址（物理地址）要查表翻译。这张表叫**页表**。

地址分两段：`页号 + 页内偏移`。翻译时只翻译页号那部分，偏移原样照抄（因为页的大小是 2 的整数次幂，一页内部的相对位置不变）。

问题来了：页表本身也存在内存里。那我要读一个数据，得先访问内存查页表（1 次），再访问内存取数据（1 次）——**变成两次访存，慢了一倍**。

于是在 CPU 里加了一个小硬件 **TLB（快表）**，把最近用过的几十条页表项抄一份放进去。绝大多数时候查 TLB 就够了，不用跑内存。**TLB 之于页表，就相当于 Cache 之于主存。**

**一次完整访存的顺序（老师最爱问这个顺序）：**

1. 查 **TLB**。命中 → 直接得到物理地址。
2. TLB 没有 → 查内存里的**页表**。页表里有 → 说明这页在内存中，顺便把这条抄进 TLB。
3. 页表里也标着"不在内存" → **缺页**！触发缺页异常，**由操作系统**把这一页从磁盘调进内存，更新页表，然后**重新执行**这条指令。
4. 拿到物理地址后，去查 **Cache**。命中就取数据，不命中就去主存取。

**一个很爱考的对比：** 这三种失败里，TLB 缺失和 Cache 缺失都是**硬件**自动处理的（几十个时钟周期），只有**缺页必须由操作系统软件处理**（要访问磁盘，几百万个时钟周期），差了好几个数量级。

**【面试就这么说】** "虚拟内存的作用是给每个进程提供独立、连续的大地址空间，同时实现进程隔离和内存保护。地址转换的过程是：虚拟地址分为页号和页内偏移，用页号查页表得到物理页框号，再拼上偏移就是物理地址，偏移部分不需要转换。因为页表存放在主存里，直接查页表会让每次访存变成两次，所以引入了 **TLB**，也就是快表，它是页表项的高速缓存，放在 CPU 内部，通常用全相联或高相联度实现。

完整的访问顺序是：先查 TLB，命中就直接得到物理地址；TLB 缺失就去查主存中的页表；如果页表显示该页不在内存，就触发缺页异常，由操作系统从磁盘调页；拿到物理地址后再去查 Cache。这里有个关键区别——**TLB 缺失和 Cache 缺失由硬件处理，而缺页必须由操作系统软件处理**，因为它涉及磁盘 I/O，代价要高好几个数量级。"

## Q8. CISC 和 RISC 有什么区别？★★★

**【一句话】** CISC 是"一句话交代一大堆事"，RISC 是"每句话只说一件事，但说得快"。

**【说人话】**

- **CISC（复杂指令集）**：指令又多又强，一条指令能干很多事。好比命令"去楼下买瓶可乐回来"。程序写起来短、省内存。但每条指令干的事不一样多，硬件电路复杂，也不好做流水线（因为每条指令花的时间差别太大）。代表：x86。
- **RISC（精简指令集）**：只保留最常用的简单指令，每条指令长度固定、干的事差不多。好比拆成"下楼""走到超市""拿可乐""付钱""上楼"。指令条数变多了，但**每条都很规整，特别适合流水线**，一条指令基本一个周期。代表：ARM、RISC-V。

**RISC 最标志性的一条规矩：只有 load 和 store 两种指令能访问内存**，其他所有运算都在寄存器之间做。这句话一定要说出来，是得分点。

**【面试就这么说】** "CISC 的思路是让单条指令尽可能强大，指令数量多、长度不固定、寻址方式多样，通常用微程序控制器实现，代表是 x86。它的优点是程序短、代码密度高，缺点是控制器复杂、各指令执行时间差异大，不利于流水线。RISC 的思路相反：只保留高频的简单指令，指令长度固定、格式规整、寻址方式少，**只有 load 和 store 指令能访问内存**，其他运算都在寄存器之间完成，通用寄存器数量多，用硬布线控制器实现。它的核心优势就是**便于流水线**，CPI 接近 1，功耗低，代表是 ARM 和 RISC-V。现在两者在融合——x86 在内部会把复杂指令翻译成类 RISC 的微操作再执行，所以是外部 CISC、内核 RISC。"

## Q9. 衡量 CPU 性能的指标有哪些？只看主频对吗？★★★

**【一句话】** 不对。**程序执行时间 = 指令条数 × CPI × 时钟周期**，主频只管住了最后一项。

**【说人话】** 主频高只说明"心跳快"，但每条指令要跳几下（CPI）、总共要执行多少条指令，这两项主频管不着。

举个例子就明白了：CISC 主频可能低，但一条指令干的事多、指令条数少；RISC 每条指令简单、CPI 接近 1，但指令条数多。两边可能跑得一样快。

三项分别被什么影响：

- **指令条数** ← 编译器优化、指令集设计
- **CPI** ← CPU 微架构（流水线好不好、Cache 命中率高不高）
- **时钟周期** ← 制造工艺、电路设计

**【面试就这么说】** "基本公式是：程序执行时间等于指令条数乘以 CPI 再乘以时钟周期，其中 CPI 是平均每条指令所需的时钟周期数，时钟周期是主频的倒数。所以只看主频是片面的——主频只影响三项中的一项。指令条数主要由编译器和指令集决定，CPI 主要由微架构决定，比如流水线设计和 Cache 命中率。其他常用指标还有 MIPS 和 GFLOPS，但 MIPS 在不同指令集之间没有可比性，所以业界更常用基准测试程序，比如 SPEC。"

## Q10. SRAM 和 DRAM 有什么区别？★★★

**【一句话】** SRAM 用"电路开关"存，稳但贵，做 Cache；DRAM 用"小电容"存，会漏电要定期刷新，便宜，做内存条。

**【说人话】**

- **SRAM**：用触发器（一般 6 个晶体管）存一位。只要通着电就一直保持，不用管它。快，但一位要 6 个管子，占地方、贵、费电。所以只用在 Cache 这种小而快的地方。
- **DRAM**：用一个电容存一位——有电荷是 1，没有是 0。结构极简单所以能做得很大很便宜。但**电容会漏电**，过一会儿电荷就跑没了，所以必须**定期刷新**（一般 2 毫秒刷一遍全部）。而且读的时候会把电荷放掉，属于**破坏性读出**，读完要重新写回去。

刷新的三种做法（顺口一句话记）：

- **集中刷新**：找一段时间集中刷完，这段时间不能访存，叫"**死区**"。
- **分散刷新**：每次读写完顺手刷一行，没死区，但把存取周期拉长了。
- **异步刷新**：前两者折中，**最常用**。

**【面试就这么说】** "SRAM 用触发器存储信息，只要不断电就能保持，不需要刷新，速度快，但一位要用六个晶体管，集成度低、功耗大、成本高，所以用作 Cache。DRAM 用电容上的电荷存储，电容会漏电所以必须定期刷新，一般是每 2 毫秒刷新一遍；它结构简单、集成度高、便宜，所以用作主存。另外 DRAM 是**破坏性读出**，读完必须重写。刷新方式有三种：集中刷新会产生不能访存的死区；分散刷新没有死区但延长了存取周期；异步刷新是折中方案，实际最常用。刷新是按**行**进行的，跟 CPU 的读写无关，所以说刷新对 CPU 是透明的。"

## Q11. 存储器为什么要分层次？★★★

**【一句话】** 因为"又快又大又便宜"做不到，只能把快的做小、大的做慢，靠局部性把它们串起来用。

**【说人话】** 从快到慢、从贵到便宜、从小到大： **寄存器 → L1 Cache → L2/L3 Cache → 主存 → 固态硬盘/机械硬盘**

速度、容量、价格这三个指标是打架的：越快的越贵，越贵就只能做得越小。所以不可能有一种存储器同时满足全部要求。分层的思路是——**让常用的东西待在快的地方**，这样平均速度接近最快的那层，而总容量接近最大的那层。能这么干的前提就是 Q3 的局部性原理。

两个相邻层之间的搬运单位不一样，这是常见追问：

- Cache ↔ 主存：以**块**为单位（几十字节），**全硬件**完成
- 主存 ↔ 硬盘：以**页**为单位（几 KB），**硬件 + 操作系统**共同完成

**【面试就这么说】** "存储系统采用层次结构，是为了在速度、容量、成本这三个互相矛盾的指标之间取得平衡——越靠近 CPU 的越快、越小、越贵。它能有效的前提是程序的局部性原理，把最近用的和邻近的数据放到高速小容量层，就能用接近 Cache 的速度提供接近主存的容量。相邻两层之间：Cache 和主存以块为单位交换，完全由硬件完成，对程序员透明；主存和辅存以页为单位交换，由硬件和操作系统共同完成。"

## Q12. Cache、寄存器、虚拟存储器三者什么关系？★★★

**【一句话】** 寄存器在 CPU 里面归编译器管，Cache 在 CPU 旁边归硬件管，虚存横跨内存和硬盘归操作系统管。

**【说人话】** 这题是把前面几题串起来考，网上出现频率非常高。三个维度对比着说就行：

||寄存器|Cache|虚拟存储器|
|---|---|---|---|
|在哪儿|CPU 内部|CPU 内/旁|主存 + 硬盘|
|解决什么问题|最快的暂存|**速度**差距|**容量**不够|
|谁来管|编译器/程序员|硬件自动|操作系统 + 硬件|
|对程序员|可见（能指定）|完全透明|基本透明|
|单位|字|块|页|
|失效代价|—|几十个周期|几百万个周期|

**【面试就这么说】** "三者都属于存储层次，但定位不同。寄存器在 CPU 内部，容量最小速度最快，由编译器分配，对程序员是可见的。Cache 位于 CPU 和主存之间，**解决的是 CPU 和主存之间的速度差距**，以块为单位交换，完全由硬件管理，对程序员透明。虚拟存储器是主存和辅存构成的层次，**解决的是主存容量不足的问题**，以页为单位交换，由操作系统和硬件共同管理。一个很关键的差别是缺失代价：Cache 缺失只要几十个时钟周期、硬件就能处理完，而缺页要访问磁盘，代价高几个数量级，必须由操作系统介入。"

## Q13. 冯·诺依曼结构的核心思想是什么？★★

**【一句话】** 存储程序——把程序像数据一样存进内存，机器自动一条条取出来执行。

**【说人话】** 在这之前的计算机，想换个任务得**重新接线**。冯·诺依曼说：把指令也编成二进制、和数据一起放进存储器，机器按地址顺序自动取指令。这样"换任务"就变成了"换一段存在内存里的数"——通用计算机由此诞生。

五大部件：**运算器、控制器、存储器、输入设备、输出设备**。（早期以运算器为中心，现代以存储器为中心）

**【面试就这么说】** "核心思想是**存储程序**：指令和数据都用二进制表示、以同等地位存放在同一个存储器中，可按地址访问，机器自动按顺序取指令并执行。硬件由运算器、控制器、存储器、输入和输出五大部件组成，早期以运算器为中心，现代计算机改为以存储器为中心。它的意义是让计算机从专用变成通用。它的主要局限是指令和数据共用一条总线，CPU 和主存之间的带宽成了瓶颈，也就是**冯·诺依曼瓶颈**。"

> **追问："和哈佛结构什么区别？"** "哈佛结构把指令和数据**分开存储、各走各的总线**，可以在同一周期同时取指令和取数据，速度更快，常见于 DSP 和单片机。现代通用 CPU 是折中的——主存统一编址是冯·诺依曼式的，但 L1 Cache 分成指令 Cache 和数据 Cache，属于**改进型哈佛结构**，这样既避免了取指和访存争用总线造成的结构冒险，又保留了统一编址的便利。"

## Q14. 计算机系统的层次结构有哪五层？★★

**【一句话】** 从底往上：微程序机器 → 传统机器 → 操作系统机器 → 汇编语言机器 → 高级语言机器。前两层是实的，上面三层是虚的。

**【说人话】** 这题看着冷门，但**网上的复试题库里出现频率极高**，而且答案很短，性价比高，务必背下来。

理解方式：每一层都在"假装"自己是一台机器，给上一层提供一套更好用的指令。

- **微程序机器**：最底层，硬件直接执行微指令。
- **传统机器**：执行机器指令（二进制）——这是**硬件和软件的分界线**。
- **操作系统机器**：提供系统调用等"广义指令"。
- **汇编语言机器**：能懂汇编，靠汇编器翻译。
- **高级语言机器**：能懂 C、Java，靠编译器翻译。

**下面两层是物理机（真实存在的硬件），上面三层是虚拟机（软件营造出来的假象）。**

**【面试就这么说】** "从下到上是：微程序机器、传统机器、操作系统机器、汇编语言机器、高级语言机器。其中微程序机器和传统机器属于**物理机**，上面三层属于**虚拟机**，是由软件营造出来的。每一层都向上层屏蔽下层的细节、提供一套更易用的接口，传统机器这一层是软硬件的分界线。这个划分的意义是让不同层次的人只需要关心自己那一层。"

## Q15. 指令周期、机器周期、时钟周期是什么关系？★★

**【一句话】** 时钟周期最小（一次心跳），若干个时钟周期 = 一个机器周期，若干个机器周期 = 一个指令周期。

**【说人话】** 套娃关系，从小到大：

- **时钟周期**（也叫节拍、T 周期）：**最小**的时间单位，就是主频的倒数。
- **机器周期**（也叫 CPU 周期）：完成一个基本操作所需的时间，通常以**访问一次内存**的时间为准。
- **指令周期**：**取出并执行完一条指令**的全部时间。

一条指令的指令周期可以拆成几个工作周期：**取指周期 → 间址周期 → 执行周期 → 中断周期**（间址周期只有用间接寻址时才有，中断周期只有有中断请求时才有）。

**【面试就这么说】** "时钟周期是最小的时间单位，等于主频的倒数；一个机器周期由若干个时钟周期组成，通常以访问一次主存的时间为基准；一个指令周期是取出并执行完一条指令所需的全部时间，由若干个机器周期组成。指令周期内部又可以划分为取指周期、间址周期、执行周期和中断周期，其中间址周期只在使用间接寻址时才有，中断周期只在响应中断时才有。不同指令的指令周期长度可能不同，比如空操作指令很短，乘除法指令就很长。"

## Q16. 机器字长、存储字长、指令字长有什么区别？★★

**【一句话】** 机器字长 = CPU 一次能算多少位；存储字长 = 一个内存单元存多少位；指令字长 = 一条指令占多少位。

**【说人话】** 这三个词长得像，专门用来考你有没有混。

- **机器字长**：CPU 一次能处理的二进制位数，通常等于通用寄存器的位数。所谓"64 位 CPU"说的就是这个。
- **存储字长**：一个存储单元里存的二进制位数。
- **指令字长**：一条指令占的位数，通常是存储字长的整数倍。

**【面试就这么说】** "机器字长是 CPU 一次能处理的二进制位数，一般和通用寄存器的位数相同，我们说 64 位处理器指的就是这个。存储字长是一个存储单元中存放的二进制位数。指令字长是一条指令占的位数，通常设计成存储字长的整数倍，这样便于取指。三者可以不相等，但为了硬件设计方便一般都取字节的整数倍。"

## Q17. IEEE 754 浮点数格式是怎样的？★★

**【一句话】** 单精度 32 位 = 1 位符号 + 8 位阶码 + 23 位尾数，阶码偏置 127；尾数前面那个 1 是隐藏的。

## Q18. 为什么计算机内部用补码？★★

**【一句话】** 因为补码能把减法变成加法，符号位还能直接参与运算，硬件省一大截。

**【说人话】** 如果用原码，做 `5 - 3` 得先比大小、判符号、再决定是加还是减，还得单独造一个减法器。

补码的妙处是：`A - B` 直接等于 `A + (B的补码)`，**减法器可以不要了，全用加法器**。而且符号位不用特殊照顾，跟着一起算就是对的。

另外两个好处：

- 零只有一种表示（原码有 +0 和 −0 两个编码，浪费还麻烦）
- 因为省下了 −0 那个编码，**能多表示一个负数**。8 位补码范围是 −128 到 +127，负的那边多一个。

**【面试就这么说】** "主要有三个原因。第一，补码把减法统一成了加法，A 减 B 等于 A 加上 B 的补码，硬件上不需要单独的减法器，复用加法器就行。第二，符号位可以直接参与运算，不需要单独处理符号，简化了控制逻辑。第三，零的表示唯一，而原码和反码都有正零和负零两种编码；也正因为省下了这个编码，n 位补码能比原码多表示一个负数，比如 8 位补码的范围是 −128 到 +127。"

---

## Q19. 常见的寻址方式有哪些？★★

**【一句话】** 关键是分清"指令里给的到底是数本身、还是数的地址、还是地址的地址"。

**【说人话】** 按"找操作数要绕几道弯"排：

- **立即寻址**：指令里直接就是这个数。最快，但数的大小受限于指令长度。
- **寄存器寻址**：指令说"数在 R3 里"。很快，不用访存。
- **直接寻址**：指令说"数在内存 1000 号"。访存一次。
- **寄存器间接寻址**：指令说"地址在 R3 里"，去 R3 拿地址，再去内存取数。这就是**指针**。
- **间接寻址**：指令说"地址在内存 1000 号"，去 1000 号拿地址，再去那个地址取数。访存两次，慢。
- **变址寻址**：地址 = 指令给的基地址 + 变址寄存器的值。**专门为数组遍历设计**——基地址是数组头，改变址寄存器就能一个个走。
- **基址寻址**：地址 = 基址寄存器 + 指令给的偏移。**专门为程序重定位设计**——程序在内存里挪了位置，只改基址寄存器就行。
- **相对寻址**：地址 = PC + 偏移。用于**跳转指令**和位置无关代码。

**基址和变址怎么区分？** 一句话：

> **基址寻址：基准由系统给、运行中不变，变的是指令里的偏移 → 用于重定位。** **变址寻址：基准由指令给、不变，变的是变址寄存器 → 用于数组循环。**

**【面试就这么说】** "主要有立即寻址、直接寻址、间接寻址、寄存器寻址、寄存器间接寻址、变址寻址、基址寻址和相对寻址。核心差别是获取操作数需要访存几次：立即和寄存器寻址不访存，直接寻址访存一次，间接寻址要两次。其中比较容易混的是基址和变址：**基址寻址的基准值由系统给出、程序运行中不变，变的是指令中的形式地址，主要用于程序重定位和多道程序**；**变址寻址的基准值由指令给出且不变，变的是变址寄存器的内容，主要用于数组的循环访问**。相对寻址以 PC 为基准，用于实现转移指令和位置无关代码。"

## Q20. 主机和外设之间有哪几种数据传送方式？哪个效率最低最高？★★

**【一句话】** 程序查询 → 中断 → DMA → 通道。CPU 参与越来越少，效率越来越高。程序查询最低，通道最高。

**【说人话】** 按"老板被打扰的程度"排：

1. **程序查询（轮询）**：CPU 站在旁边不停问"好了吗？好了吗？"，什么都干不了。**效率最低，但最简单。**
2. **程序中断**：设备好了自己来叫。CPU 平时能干别的活。但**每传一个字就要中断一次**，对高速设备（比如硬盘）还是太频繁。
3. **DMA**：交代一次，设备直接和内存对接，传完整块再报告一次。**适合磁盘这种高速块设备。**
4. **通道 / IOP**：有个专门的"小 CPU"负责 I/O，能执行通道程序、管好几台设备。**CPU 参与最少，效率最高。**

**【面试就这么说】** "有四种：程序查询、程序中断、DMA 和通道方式，本质区别是 CPU 参与的程度。程序查询方式下 CPU 要不断查询设备状态，完全被占用，**效率最低**但硬件最简单。程序中断方式下设备准备好后主动请求，CPU 可以并行做别的事，但每传送一个字都要中断一次，对高速设备开销大。DMA 让外设直接和主存交换数据，CPU 只在传输前初始化和传输后响应一次结束中断，适合磁盘这类高速块设备。通道方式用专门的 I/O 处理器执行通道程序，可以管理多台设备，**CPU 参与最少、效率最高**。"

## Q21. Cache 的替换算法有哪些？★★

**【一句话】** 随机、FIFO、LRU、LFU。实际主要用 LRU（或它的简化版）。

**【说人话】** Cache 满了，该踢谁走？

- **随机**：抓阄。实现最简单，效果不稳定。
- **FIFO（先进先出）**：谁来得最早踢谁。简单，但可能踢掉一直在用的老员工。还有个坑叫 **Belady 异常**——容量变大了，缺失反而变多。
- **LRU（最近最少使用）**：谁最久没用踢谁。**最符合局部性原理**，命中率高，是主流。但要给每行维护计数器，硬件贵，所以实际常用"伪 LRU"来近似。
- **LFU（最不经常使用）**：谁用得次数最少踢谁。问题是早期红过一阵的块，次数攒得高，之后再没人用也赖着不走。

**注意：直接映射不需要替换算法**，因为位置是唯一的，只能踢那一个。

**【面试就这么说】** "常用的有四种。随机替换实现最简单但命中率不稳定。FIFO 替换最早调入的块，实现简单，但可能把仍在频繁使用的块换出去，而且会出现 Belady 异常，就是容量增大缺失反而增多。LRU 替换最久未被访问的块，最符合时间局部性，命中率最高，但需要为每行维护访问历史，硬件开销大，所以实际常用伪 LRU 做近似。LFU 按访问次数替换，缺点是早期高频访问的块会长期占用不被淘汰。另外要注意，**直接映射方式不需要替换算法**，因为每个块的位置是唯一确定的。"

---

## Q22. 总线是什么？有哪些分类和仲裁方式？★★

**【一句话】** 总线是多个部件共用的"公路"，特点是分时共享；因为共用，所以要仲裁谁先走。

**【说人话】** 总线最本质的特点：**同一时刻只能有一个部件在上面发信息**（分时 + 共享）。

按传的内容分三种：

- **数据总线**：位数决定一次能传多少数据，**双向**
- **地址总线**：位数决定能寻址多大空间，**单向**（只能 CPU 发出去）
- **控制总线**：传命令和状态，双向

**仲裁**（谁能用总线）：

- **链式查询**：设备串成一串，同意信号从头传到尾，**离得越近优先级越高**。线最少最简单，但优先级写死了，而且中间断一个后面全完蛋。
- **计数器定时查询**：用计数器轮流点名，**改计数初值就能改优先级**，灵活一些。
- **独立请求**：每个设备一对专线，**响应最快、最灵活，但线最多**。

**【面试就这么说】** "总线是多个部件共享的信息传输通道，最本质的特点是**分时和共享**——同一时刻只能有一个部件发送信息。按传输内容分为数据总线、地址总线和控制总线，其中数据总线的位数决定一次传输的数据量，地址总线的位数决定寻址空间，而且地址总线是**单向**的，只能由 CPU 发出。

仲裁分集中式和分布式。集中式有三种：链式查询最简单、线数最少，但优先级固定、对故障敏感；计数器定时查询通过设定计数初值可以灵活改变优先级；独立请求方式每个设备有专用的请求线和允许线，响应最快、最灵活，但线数最多、控制最复杂。分布式仲裁则没有中央仲裁器，各设备把优先级码送上总线自行比较。"

---

## Q23. 硬布线控制器和微程序控制器有什么区别？★★

**【一句话】** 硬布线是"用电路硬做"，快但难改；微程序是"用软件的思路做"，好改但慢。

**【说人话】** 控制器要在每个时刻发出正确的控制信号。两种做法：

- **硬布线**：用一堆与门或门直接搭出来。**像写死的电路**，快，但要改一条指令得重新设计电路。适合指令简单规整的 **RISC**。
- **微程序**：把每条机器指令翻译成一段"微程序"，存在一个叫控制存储器的小 ROM 里，执行时一条条读出来。**像在解释执行**，规整、好改好扩展，但每次都要读一次控制存储器，慢。适合指令复杂的 **CISC**。

一句话：**硬布线是硬件思路做控制，微程序是软件思路做控制。**

**【面试就这么说】** "硬布线控制器用组合逻辑电路直接产生控制信号，速度快，但设计复杂、一旦定型难以修改和扩展，适合指令规整的 RISC。微程序控制器把每条机器指令对应成一段微程序，存放在控制存储器中，执行时通过取微指令来产生控制信号，结构规整、易于修改和扩展，但因为要访问控制存储器所以速度较慢，适合指令复杂的 CISC。简单说，**硬布线是用硬件的方式实现控制，微程序是用软件的思路实现控制**。"

## Q24. 什么是 Amdahl 定律？★

**【说人话】** 你优化某一部分能带来多少总体提升，取决于**这部分原来占多大比例**。只占 10% 的东西，优化到无限快，总体也只快 11%。

**【面试就这么说】** "阿姆达尔定律说的是系统加速比受限于可优化部分所占的时间比例。它有两个直接推论：一是优化要优先针对占比大的部分，抓主要矛盾；二是并行计算的加速有天花板，串行部分决定了上限。"

> 💡 **接研究**："这个在多卡训练里特别直观——卡越多，梯度同步的通信占比越大，加速比就越偏离线性。所以才有梯度累积、通信和计算重叠这些优化，本质都是在压缩不可并行部分的占比。"

---

## Q25. Cache 缺失分哪几类？★

**【说人话】** 叫 **3C**：

- **强制缺失**：第一次访问，谁也躲不掉 → 加大块、做预取
- **容量缺失**：Cache 太小装不下 → 只能加大容量
- **冲突缺失**：明明有空位却因为映射规则被迫替换 → 提高相联度

**全相联 Cache 没有冲突缺失**，因为它想放哪儿放哪儿。

---

## Q26. 平均访存时间怎么算？怎么优化 Cache？★

**【一句话】** **平均访存时间 = 命中时间 + 缺失率 × 缺失代价**。

**【说人话】** 三个变量，三条优化路线，而且互相打架：

- 降**命中时间** → Cache 做小、相联度做低
- 降**缺失率** → 容量做大、块做大、相联度做高
- 降**缺失代价** → 加多级 Cache、加写缓冲

前两条明显矛盾，所以才有了多级 Cache 的分工：**L1 做得小而快（优化命中时间），L2/L3 做得大（优化缺失率）**。

---

## Q27. 补码加减法怎么判断溢出？★

**【说人话】** 两种看法：

1. 看**符号位的进位和最高数值位的进位**是否相同，不同就是溢出。
2. 看符号：正 + 正 = 负，或者负 + 负 = 正，就是溢出。（一正一负相加永远不会溢出）

硬件上常用**双符号位法**（变形补码），两个符号位不一致就溢出，而且第一位还能告诉你是正溢出还是负溢出。

---

## Q28. 大端和小端是什么？★

**【说人话】** 数字 `0x12345678` 存进内存，高位字节 `12` 放前面还是后面？

- **大端**：`12` 放低地址，符合人的书写顺序。**网络传输用大端**，所以叫网络字节序。
- **小端**：`78` 放低地址。x86 用小端。

**实际影响**：跨平台传二进制数据要做字节序转换，不然读出来是乱的。

---

## Q29. 超标量、超流水、VLIW 各是什么？★

**【说人话】** 都是想在一个周期里干更多事：

- **超标量**：造多套执行部件，一个周期同时发射多条指令 → **靠空间换**，CPI 可以小于 1
- **超流水**：把流水线切得更细，主频拉高 → **靠时间换**
- **VLIW（超长指令字）**：让**编译器**提前把能并行的指令打包成一条超长指令，硬件不做相关性检查 → 硬件简单，但极度依赖编译器

还可以提一句 **Tomasulo 算法 / 乱序执行**：用保留站和寄存器重命名消除假相关，实现乱序执行、按序提交。

---

## Q30. 同步总线和异步总线的区别？★

**【说人话】**

- **同步**：大家听同一个节拍器。简单、快，但**节拍必须按最慢的设备来定**，只适合速度接近的部件。
- **异步**：没有统一时钟，靠**握手信号**（我问"好了吗"，你答"好了"）。能连速度差很大的设备，但控制复杂、慢。异步又分不互锁、半互锁、全互锁，**全互锁最可靠也最慢**。

---

## Q31. DMA 有哪几种传送方式？★

- **停止 CPU 访存**：DMA 期间 CPU 完全让出总线，简单高效但 CPU 长时间闲置
- **周期窃取**：只在需要时偷一两个存储周期，其余时间 CPU 正常跑，**最常用**
- **交替访存**：把一个存储周期切成两半，一半给 CPU 一半给 DMA，不用申请释放总线，效率最高但硬件复杂

**① 局部性原理 → 数据加载与显存访问** "我做大模型微调实验时，数据加载和显存访问的效率对训练吞吐影响很大。这本质上就是存储层次的问题——GPU 显存相当于主存，片上 SRAM 相当于 Cache，HBM 带宽相当于总线带宽。像 FlashAttention 之所以快，核心就是把注意力计算分块，让中间结果尽量留在片上 SRAM 里，减少对 HBM 的往返读写，这就是典型的利用局部性做优化。"

# 第五部分：临进考场前十分钟速扫

- 冯·诺依曼核心 = **存储程序**；瓶颈 = CPU 与主存的带宽
- 五层结构：微程序 / 传统 / 操作系统 / 汇编 / 高级语言，**前两层是物理机**
- **CPU 时间 = 指令数 × CPI × 时钟周期**
- 套娃：**时钟周期 < 机器周期 < 指令周期**
- 用补码的三个理由：**减法变加法、符号位参与运算、零唯一且多一个负数**
- IEEE754 单精度 **1+8+23 偏置 127**；双精度 **1+11+52 偏置 1023**；**尾数隐含 1**
- 局部性：**时间（刚用过还会用）+ 空间（用了它还会用旁边）**
- SRAM 触发器不刷新做 Cache；DRAM 电容要刷新做主存，**破坏性读出**
- Cache 映射：直接（取模）/ 全相联（随便放）/ **组相联（组间直接、组内全相联，实际用这个）**
- 写策略搭配：**写回 + 写分配**，**写直通 + 非写分配**
- **平均访存时间 = 命中时间 + 缺失率 × 缺失代价**
- 访存顺序：**TLB → 页表 →（缺页）→ Cache → 主存**
- **Cache 缺失硬件管，缺页必须操作系统管**
- 五级流水：**取指 / 译码 / 执行 / 访存 / 写回**
- **流水线不缩短单条指令时间，只提高吞吐率**
- 三冒险：结构（分离 I/D Cache）、数据（**转发**，load-use 必停一拍）、控制（分支预测）
- RISC 标志：**只有 load/store 访存**、指令定长、便于流水
- I/O 四方式效率：**程序查询最低 < 中断 < DMA < 通道最高**
- DMA vs 中断四点：**通路不同 / 响应时机不同（指令结束 vs 总线周期结束）/ DMA 优先级高 / DMA 不保护现场**
- 中断隐指令 = **硬件自动做的三件事**（关中断、保断点、引出服务程序），指令系统里没有它
- 服务程序里**开中断**是为了**中断嵌套**
- 地址总线**单向**，数据和控制总线双向
- 仲裁三种：链式查询 / 计数器定时查询 / 独立请求

# 第六部分：卡住了怎么办

别沉默，也别硬编。三句话备着：

1. **只记得框架**："这个细节我记得不是特别牢，但它要解决的问题我是清楚的，是……，大致思路应该是……"
2. **绕到熟悉的地方**："我对这块的理解主要来自做 XX 时遇到的类似情况，比如……，不知道理解得对不对。"
3. **实在不会**："这一点我确实掌握得不扎实，回去我会补上，谢谢老师。"

老师问这些题，不是要一个标准答案，是想看**你的思路顺不顺、说话清不清楚、诚不诚实**。答错一题不致命，编一个漏洞百出的答案才致命。
