# 计算机网络 · 保研复试口语复习手册

> 面向纯口头问答，不写公式、不画图、不算题。 每题两层：【通俗讲解】用来理解，【面试怎么答】是可以直接背出口的话。 优先级标注：★★★ 必背，★★ 常问，★ 了解即可。

---

## 第 0 章 答题总原则

**三句话结构**（几乎所有网络题都能套）：

1. **是什么** —— 一句定义。
2. **为什么/怎么做** —— 机制或原因，2~4 点。
3. **有什么影响/对比** —— 优缺点、和谁对比、实际用在哪。

**几条口头表达的注意事项**：

- 别一上来背定义八股，先说"它要解决的问题是什么"，老师更爱听。
- 说不清的地方主动收口："这块我记得的是……细节可能不太准确。" 比硬编强得多。
- 被追问"为什么"时不要慌，网络里几乎所有设计的答案都落在三个词上：**可靠性、效率、兼容性**。
- 遇到完全没准备的题，往你熟的层上引：比如问你某个陌生协议，可以说"我不太确定它的细节，但从它工作在传输层这一点推断，它需要解决 X 问题"。

## 第 1 章 体系结构与参考模型

### Q1.1 OSI 七层和 TCP/IP 四层分别是什么？★★★

**【通俗讲解】** 分层就是把"把数据从我的电脑送到你的电脑"这件复杂的事拆成若干个独立的小事，每层只管自己那一件，层与层之间只通过固定接口打交道。好处是某一层的技术换了（比如从网线换成 WiFi），上面几层完全不用改。

OSI 七层从下往上：物理、数据链路、网络、传输、会话、表示、应用。 TCP/IP 四层：网络接口层、网际层、传输层、应用层。 实际教学常用**五层模型**：物理、数据链路、网络、传输、应用。

**【面试怎么答】** "OSI 是理论上的七层模型，从下往上是物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。TCP/IP 是实际使用的四层，把 OSI 的上三层合成了应用层，下两层合成了网络接口层。我们平时分析问题常用五层模型。

各层职责简单说：物理层负责比特流在物理介质上传输；数据链路层负责在相邻结点之间把比特组织成帧、做差错检测；网络层负责跨网络的路由和寻址，把分组从源主机送到目的主机；传输层负责端到端的进程间通信，提供可靠或不可靠的数据传输；应用层直接为用户进程提供服务。

分层的核心好处是解耦，每层只需要向上提供服务、向下调用服务，某一层的实现变化不影响其他层。"

### Q1.2 各层的典型协议和设备？★★★

**【面试怎么答】** "按层说：

- 应用层：HTTP、HTTPS、DNS、FTP、SMTP、DHCP、SSH。
- 传输层：TCP、UDP。
- 网络层：IP、ICMP、ARP、路由协议 RIP/OSPF/BGP。（ARP 严格说位置有争议，408 教材放在网络层，也有教材放链路层。）
- 数据链路层：以太网协议、PPP。
- 物理层：各种物理规范。

设备方面：物理层是中继器和集线器；数据链路层是网桥和交换机；网络层是路由器；传输层以上是网关或者主机上的软件。"

### Q1.3 数据在各层叫什么？封装过程是怎样的？★★

**【通俗讲解】** 就像寄快递：你写好信（应用层数据），装进信封写上收件人（传输层加端口），再装进箱子写上地址（网络层加 IP），再贴上快递单交给快递员（链路层加 MAC）。每往下走一层就多包一层头。接收方反过来一层层拆。

**【面试怎么答】** "数据在应用层叫报文，传输层叫报文段（TCP）或用户数据报（UDP），网络层叫 IP 数据报或分组，数据链路层叫帧，物理层是比特流。

发送时数据自上而下，每层加上本层的首部，这叫封装；接收时自下而上逐层剥掉首部，这叫解封装。中间的路由器只需要处理到网络层，交换机只处理到数据链路层。"

### Q1.4 交换机、路由器、集线器的区别？★★

**【面试怎么答】** "三者工作层次不同。

集线器在物理层，它就是把信号简单地放大转发到所有端口，所有端口在同一个冲突域也在同一个广播域，效率很低，现在基本淘汰了。

交换机在数据链路层，根据 MAC 地址表做转发，只把帧送到目标端口。它能隔离冲突域，但不能隔离广播域，一个交换机下面还是一个广播域。

路由器在网络层，根据 IP 地址和路由表在不同网络之间转发分组。它既隔离冲突域也隔离广播域，是划分网络的边界。"

## 第 2 章 物理层（低频，会说两句就行）

### Q2.1 物理层做什么？★

**【面试怎么答】** "物理层的任务是在传输介质上传输原始比特流，它规定的是接口的机械特性、电气特性、功能特性和规程特性，比如接口形状、电压表示 0 和 1、每根线的作用。它不关心数据的含义。"

### Q2.2 信道容量相关（奈奎斯特和香农）★

**【面试怎么答】** "奈奎斯特定理描述的是理想无噪声信道下，带宽限制了码元传输速率的上限；香农定理描述有噪声信道下，信道容量由带宽和信噪比共同决定。结论上说，提高带宽和提高信噪比都能提升极限速率，但信噪比的提升有边际效应。"

### Q2.3 曼彻斯特编码？★

**【面试怎么答】** "曼彻斯特编码把每个码元中间做一次电平跳变，用跳变方向表示 0 和 1。好处是自带时钟同步信息，接收方不需要单独的时钟线；代价是占用带宽翻倍。以太网早期用的就是它。"

## 第 3 章 数据链路层

### Q3.1 数据链路层要解决什么问题？★★

**【面试怎么答】** "三个核心问题：封装成帧，也就是确定一帧的开始和结束；差错控制，检测传输中出错的比特；流量控制，防止发送方压垮接收方。此外在共享介质的网络里还要做介质访问控制，决定谁什么时候能发。"

### Q3.2 CSMA/CD 是什么？为什么以太网需要它？★★★

**【通俗讲解】** 想象一屋子人共用一个话筒讨论。规则是：想说话先听有没有人在说（先听后发）；开口了还要继续听，如果发现有人同时开口就是撞车了（边听边发）；一旦撞车立刻闭嘴（冲突停发）；然后各自随机等一段时间再试，等的时间不一样就不会一直撞（随机重发）。

**【面试怎么答】** "CSMA/CD 是载波监听多点接入/碰撞检测，用在早期的共享总线式以太网上，因为多个主机共用一条信道，需要解决同时发送导致碰撞的问题。

规则可以概括成十六个字：先听后发、边听边发、冲突停发、随机重发。检测到冲突后使用二进制指数退避算法，冲突次数越多，随机等待的区间越大。

这里有个关键点是最小帧长的限制，以太网规定最小帧长 64 字节。原因是主机必须在帧发送完毕之前就能检测到冲突，如果帧太短，发完了冲突信号才传回来，主机就意识不到这一帧失败了。

现在的交换式以太网是全双工的，每个端口独占链路，已经不需要 CSMA/CD 了。"

### Q3.3 CSMA/CA 和 CSMA/CD 的区别？★★

**【面试怎么答】** "CA 是碰撞避免，用在无线局域网 WiFi 上。区别的根源是无线环境下没法边发边听：无线信号自己发出去的功率远大于收到的，检测不到别人的信号；而且存在隐蔽站问题，两个站互相听不到但都能干扰接收方。

所以无线里做不到检测冲突，只能尽量避免冲突。手段包括：发送前等待一个随机退避时间；用 RTS/CTS 帧先预约信道；每收到一帧都要回 ACK 确认，没收到 ACK 就认为丢了要重传。"

### Q3.4 差错检测怎么做？CRC 的思路？★★

**【面试怎么答】** "链路层一般只做检错不做纠错，出错就丢弃重传。常用循环冗余校验 CRC：收发双方约定一个生成多项式，发送方用数据除以它，把余数作为冗余码附在帧尾；接收方用同样的除数去除收到的整个帧，余数为 0 就认为没错。

CRC 的检错能力很强而且硬件实现简单，所以广泛用于链路层。需要注意 CRC 只能检错不能定位错误，也不能保证百分之百检出。"

### Q3.5 停止等待、后退 N 帧、选择重传的区别？★★

**【通俗讲解】**

- 停止等待：发一个等一个确认，最慢但最简单。
- 后退 N 帧（GBN）：可以连发一批，但接收方只按顺序收，中间丢一个，后面全部作废重发。
- 选择重传（SR）：接收方有缓存，能收下乱序的帧，只重传丢的那一个。

**【面试怎么答】** "三者都是可靠传输的实现方式，区别在信道利用率和实现复杂度的权衡。

停止等待协议发一帧等一个 ACK，信道利用率很低。后退 N 帧用滑动窗口连续发送，但接收窗口大小为 1，只接受按序到达的帧，一旦某帧出错，它之后已经发出的帧都要重传，所以叫后退 N 帧。选择重传的接收窗口大于 1，能缓存乱序帧，只重传出错的那一帧，效率最高但需要接收方有缓存，实现复杂。

窗口大小上有个约束：GBN 的发送窗口最大是 2 的 n 次方减 1，SR 的发送窗口和接收窗口最大都是 2 的 n 次方除以 2，n 是序号位数。"

## 第 4 章 网络层

### Q4.1 网络层的核心任务？★★

**【面试怎么答】** "网络层负责把分组从源主机送到目的主机，跨越多个网络。核心是两件事：路由，也就是决定分组走哪条路径，这是控制平面的工作；转发，也就是路由器收到一个分组后查表把它送到某个输出端口，这是数据平面的工作。

另外网络层还要处理异构网络互联，比如不同网络的 MTU 不同就需要分片。IP 提供的是无连接、不可靠、尽最大努力交付的服务，可靠性交给上层的 TCP 来保证。"

### Q4.2 IP 地址的分类和子网掩码？★★★

**【面试怎么答】** "IPv4 地址 32 位，传统上分 A、B、C、D、E 五类，A 类前 8 位是网络号，B 类前 16 位，C 类前 24 位，D 类是组播，E 类保留。

这种分类方式浪费严重，所以后来引入子网划分和 CIDR。CIDR 取消了类的概念，用斜线记法，比如 192.168.1.0/24 表示前 24 位是网络前缀。子网掩码就是用来标识网络号占多少位的，把 IP 地址和子网掩码按位与，得到的就是网络地址。

还要记住几个私有地址段：10 开头的 A 类一段，172.16 到 172.31，以及 192.168 开头的，这些地址只在内网使用，不在公网上路由。127 开头是回环地址。"

### Q4.3 NAT 是什么？为什么需要？★★★

**【通俗讲解】** 一栋楼只有一个门牌号，楼里有很多住户。快递统一送到楼下，前台记一个本子：这个包裹是 301 的，那个是 502 的。NAT 就是这个前台。

**【面试怎么答】** "NAT 是网络地址转换，主要目的是缓解 IPv4 地址枯竭。内网主机使用私有地址，出口路由器在转发时把源 IP 换成自己的公网 IP，同时把源端口也换掉，并在 NAT 表里记录这个映射关系。回来的数据包根据目的端口查表，还原成内网地址。

因为同时转换 IP 和端口，所以严格说常用的是 NAPT，一个公网 IP 可以支撑很多台内网主机。

副作用是打破了端到端的通信模型，外网无法主动发起连接到内网主机，所以 P2P 应用需要打洞或者中转服务器。"

### Q4.4 ARP 协议的工作过程？★★★

**【通俗讲解】** 你知道对方的身份证号（IP），但是快递员只认门牌号（MAC）。于是你在楼道里喊一嗓子："身份证号 XXX 的人在吗？"（广播请求）本人听到了单独回你一句："是我，我住 502。"（单播回应）然后你把这个对应关系记在小本子上，下次不用再喊。

**【面试怎么答】** "ARP 解决的是同一局域网内由 IP 地址获取 MAC 地址的问题。因为数据链路层转发靠的是 MAC 地址，而上层只知道 IP。

过程是：主机先查自己的 ARP 缓存，如果没有，就在局域网内广播一个 ARP 请求帧，问'谁的 IP 是这个'。局域网内所有主机都会收到，只有 IP 匹配的那台主机单播回复一个 ARP 响应，携带自己的 MAC。请求方把结果写入 ARP 缓存，缓存有过期时间。

注意 ARP 只在同一个局域网内有效。如果目的主机在另一个网络，源主机是去解析默认网关（路由器）的 MAC，把帧交给路由器，由路由器继续往下转发。"

**追问：ARP 欺骗是什么？** "ARP 没有认证机制，任何主机都可以伪造 ARP 响应，声称某个 IP 对应自己的 MAC，从而把流量引到自己这里，形成中间人攻击。防御手段包括静态 ARP 绑定、ARP 检测工具、交换机的动态 ARP 检查。"

### Q4.5 ICMP 是什么？ping 和 traceroute 的原理？★★★

**【面试怎么答】** "ICMP 是网际控制报文协议，用来在 IP 层传递差错报告和查询信息，它的报文封装在 IP 数据报里，属于网络层。

ping 用的是 ICMP 的回送请求和回送回答报文，发出去再收回来，用来测试连通性和往返时延。

traceroute 的思路很巧妙：它发出一系列 IP 数据报，把 TTL 依次设为 1、2、3……TTL 为 1 时第一跳路由器把它减到 0 就丢弃，并回送一个 ICMP 超时报文，这样就暴露了第一跳的地址；TTL 为 2 时暴露第二跳，以此类推，最终拼出整条路径。Linux 版本发的是 UDP 报文，到达目的主机后靠端口不可差错报文来判断结束。"

### Q4.6 IP 分片是怎么回事？★★

**【面试怎么答】** "不同链路的 MTU 不同，以太网通常是 1500 字节。如果一个 IP 数据报超过了下一跳链路的 MTU，路由器就要把它切成多个分片分别传输，到达最终目的主机后再重组，中间路由器不负责重组。

IP 首部里有三个字段配合完成这件事：标识字段标记这些分片属于同一个原始数据报，标志字段里的 MF 位表示后面还有没有分片、DF 位表示是否允许分片，片偏移字段表示这一片在原始数据报中的位置。

分片的问题是任何一片丢了整个数据报都要重传，效率低。所以现在倾向于用路径 MTU 发现，让发送方一开始就发送足够小的包，TCP 的 MSS 协商就是干这个的。"

### Q4.7 路由协议 RIP、OSPF、BGP 的区别？★★

**【面试怎么答】** "先分类：RIP 和 OSPF 是内部网关协议，用在一个自治系统内部；BGP 是外部网关协议，用在自治系统之间。

RIP 是距离向量协议，用跳数作为度量，每 30 秒和相邻路由器交换整张路由表。它简单但有明显缺点：最大跳数 15，超过就认为不可达，只适合小网络；而且收敛慢，存在'坏消息传得慢'的问题。

OSPF 是链路状态协议，每个路由器把自己周围链路的状态用洪泛法发给整个区域，每台路由器都拿到全网拓扑，然后用 Dijkstra 算法算最短路径。收敛快，支持划分区域来控制规模，度量可以自定义，是大型网络的主流选择。

BGP 是路径向量协议，它交换的是到达某个网络所经过的自治系统序列。BGP 关心的不只是最短，更多是策略，比如出于商业关系不走某条路。BGP 底层跑在 TCP 上。"

### Q4.8 IPv6 相比 IPv4 的改进？★

**【面试怎么答】** "最直接的是地址从 32 位扩展到 128 位，彻底解决地址枯竭。此外首部做了简化，长度固定为 40 字节，去掉了首部校验和，把可选字段挪到扩展首部里，提高路由器转发效率。IPv6 不允许中间路由器分片，只能由源主机分片。还内置了对 IPsec 的支持，并且用邻居发现协议取代了 ARP。"

## 第 5 章 传输层（重点中的重点）

### Q5.1 TCP 和 UDP 的区别？★★★

**【面试怎么答】** "从几个维度对比：

连接性上，TCP 是面向连接的，通信前要三次握手建立连接；UDP 是无连接的，直接发。

可靠性上，TCP 保证数据无差错、不丢失、不重复、按序到达；UDP 尽最大努力交付，不保证。

传输方式上，TCP 是面向字节流的，没有消息边界；UDP 是面向报文的，应用层交下来多大就发多大，保留边界。

服务对象上，TCP 只能一对一；UDP 支持一对一、一对多、多对多，可以广播组播。

开销上，TCP 首部 20 字节起，有拥塞控制和流量控制机制，开销大；UDP 首部只有 8 字节，几乎没有额外机制，效率高、时延低。

适用场景：TCP 用在文件传输、网页浏览、邮件这些对正确性要求高的场景；UDP 用在实时音视频、直播、DNS 查询、游戏这些对时延敏感、能容忍少量丢包的场景。DNS 用 UDP 是因为查询响应短、要求快，但响应超过 512 字节或者区域传送时会切到 TCP。"

### Q5.2 TCP 三次握手的过程？★★★

**【面试怎么答】** "第一次，客户端发送 SYN 报文，携带自己的初始序号 seq=x，客户端进入 SYN_SENT 状态。

第二次，服务端收到后回复 SYN+ACK，携带自己的初始序号 seq=y，同时确认号 ack=x+1，服务端进入 SYN_RCVD 状态。

第三次，客户端回复 ACK，确认号 ack=y+1，此时客户端进入 ESTABLISHED；服务端收到后也进入 ESTABLISHED，连接建立。

需要注意第三次握手的报文是可以携带数据的，前两次不行。"

### Q5.3 为什么是三次握手，不是两次或四次？★★★

**【通俗讲解】** 握手的本质是确认双方的收发能力都正常。

- 第一次：服务端知道了"客户端能发"。
- 第二次：客户端知道了"服务端能收、能发"，同时确认了"自己能发能收"。
- 第三次：服务端才知道了"客户端能收"。

少一次，服务端就不知道自己发出去的东西对方能不能收到。

**【面试怎么答】** "主要有两个理由。

第一，从确认双方收发能力的角度。两次握手后，客户端确认了双方的收发都正常，但服务端只知道客户端能发，不知道客户端能不能收到自己的回复，所以必须有第三次。

第二，也是教材上强调的，防止已失效的连接请求报文突然又传到服务端。假设客户端发的第一个 SYN 在网络中滞留了很久，客户端超时重发建立并关闭了连接，之后这个旧 SYN 才到达服务端。如果只有两次握手，服务端一收到就认为连接建立了，分配资源等待数据，但客户端根本不会理它，这些资源就白白浪费了。三次握手的话，客户端收到这个确认发现不是自己想要的，不会发第三次 ACK，服务端等不到就会释放资源。

不用四次是因为服务端的 SYN 和 ACK 可以合并在一个报文里发出，没必要拆开，三次已经够用了。"

### Q5.4 四次挥手的过程？为什么要四次？★★★

**【面试怎么答】** "过程是：

客户端发 FIN，进入 FIN_WAIT_1，表示我没有数据要发了。 服务端回 ACK，进入 CLOSE_WAIT；客户端收到后进入 FIN_WAIT_2。这时候是半关闭状态，客户端不再发数据但还能收。 服务端把剩余数据发完后，发送自己的 FIN，进入 LAST_ACK。 客户端回 ACK，进入 TIME_WAIT，等待 2MSL 后关闭；服务端收到 ACK 后直接进入 CLOSED。

需要四次的原因是 TCP 是全双工的，两个方向的连接要分别关闭。服务端收到客户端的 FIN 时，可能还有数据没发完，所以只能先回一个 ACK 表示'我知道了'，等数据发完了再单独发 FIN。握手时 SYN 和 ACK 能合并，挥手时 ACK 和 FIN 中间隔着数据发送，通常合并不了。"

### Q5.5 TIME_WAIT 为什么要等 2MSL？★★★

**【面试怎么答】** "MSL 是报文最大生存时间。等待 2MSL 有两个原因。

第一，保证最后一个 ACK 能够到达对方。如果这个 ACK 丢了，服务端会超时重传 FIN，客户端还在 TIME_WAIT 状态就能重新回一个 ACK。如果客户端直接关了，服务端收不到 ACK 会一直重传，最后异常关闭。一来一回正好是 2 个 MSL。

第二，让本次连接产生的所有报文段都从网络中消失。否则如果马上用相同的四元组建立新连接，旧连接的迟到报文可能被新连接误收。

实际工程里 TIME_WAIT 过多会占用端口资源，服务器上常通过开启端口复用等参数来缓解。"

**追问：为什么是主动关闭方进入 TIME_WAIT？** "因为最后一个 ACK 是主动关闭方发的，只有它需要留在原地应对可能的 FIN 重传。"

**追问：CLOSE_WAIT 过多说明什么？** "说明服务端的应用程序收到了 FIN 但没有调用 close，通常是代码里忘记关闭连接或者业务逻辑阻塞了，属于典型的应用层 bug。"

### Q5.6 TCP 如何保证可靠传输？★★★

**【面试怎么答】** "可以概括成六点：

第一，数据分块和编号。TCP 把字节流分成合适大小的报文段，每个字节都有序号，接收方据此排序去重。

第二，校验和。首部和数据都参与校验，出错就丢弃并且不确认。

第三，确认与超时重传。发出的报文段如果在 RTO 时间内没收到确认就重传，RTO 是根据 RTT 动态估算的。

第四，累积确认和快速重传。接收方对按序到达的最高序号做累积确认；发送方连续收到三个重复 ACK 就立即重传，不必等超时。

第五，流量控制。用滑动窗口保证不会发送超过接收方处理能力的数据。

第六，拥塞控制。感知网络状况调整发送速率，避免拥塞加剧导致大量丢包。"

### Q5.7 滑动窗口和流量控制？★★★

**【通俗讲解】** 接收方每次回 ACK 的时候都会捎带一句"我还能再收 N 个字节"，发送方就按这个数控制自己发多少，不会把对方缓冲区撑爆。

**【面试怎么答】** "流量控制解决的是发送方发太快、接收方来不及处理的问题，是端到端的。

实现方式是接收方在 TCP 首部的窗口字段里告诉发送方自己剩余的缓冲区大小，发送方的发送窗口不能超过这个值。发送窗口随着确认的到来向前滑动，所以叫滑动窗口。

这里有个死锁风险：如果接收方通告窗口为 0，发送方就停下等待；后来接收方缓冲区空出来发了一个非零窗口通知，但这个通知丢了，双方就会互相等待。TCP 的解决办法是发送方启动一个持续计时器，超时后发送零窗口探测报文，主动去问对方现在的窗口是多少。"

### Q5.8 拥塞控制的四个算法？★★★

**【通俗讲解】** 把网络想成一条路。慢开始是先试探性地少发一点，发现没堵就翻倍加；到了一个阈值就改成小心翼翼地一点点加（拥塞避免）；一旦发现堵了（超时），认为情况很严重，直接退回起点重来；如果只是零星丢包（收到三个重复 ACK），说明网络还通着，就只退一半（快恢复）。

**【面试怎么答】** "拥塞控制是全局性的，关注的是整个网络的承载能力，和流量控制关注接收方能力不同。

慢开始：连接建立时拥塞窗口 cwnd 设为 1 个 MSS，每收到一个确认就翻倍，实际上是指数增长。虽然叫慢开始，但增长其实很快，慢指的是起点低。

拥塞避免：当 cwnd 达到慢开始门限 ssthresh 后，改为每经过一个往返时延只增加 1 个 MSS，变成线性增长，增长得更谨慎。

超时重传发生时：认为网络严重拥塞，把 ssthresh 设为当前 cwnd 的一半，cwnd 重置为 1，重新开始慢开始。

快重传：接收方收到失序报文时要立即发重复 ACK，发送方一旦收到三个重复 ACK 就立刻重传丢失的报文段，不用等超时。

快恢复：配合快重传使用。因为还能收到重复 ACK 说明网络还能传数据，所以不必退到 1。把 ssthresh 设为 cwnd 的一半，cwnd 也设为这个新的 ssthresh，然后直接进入拥塞避免的线性增长。

实际的发送窗口取拥塞窗口和接收方通告窗口的较小值。"

### Q5.9 流量控制和拥塞控制的区别？★★★

**【面试怎么答】** "目的和作用对象都不同。流量控制是端到端的，防止发送方压垮接收方，由接收方通过通告窗口来控制。拥塞控制是全局的，防止过多数据注入网络导致路由器缓存溢出，由发送方根据网络反馈自己判断和调整。

一个是照顾对方的处理能力，一个是照顾中间网络的承载能力。真正的发送窗口是两者的最小值。"

### Q5.10 TCP 粘包问题是什么？怎么解决？★★★

**【通俗讲解】** TCP 眼里数据就是一条连续的水流，你连着倒了三杯水进去，接收方那边看到的是一整摊水，分不清哪杯是哪杯。

**【面试怎么答】** "粘包的根本原因是 TCP 面向字节流，不保留应用层的消息边界。发送方连续发送的多个小消息可能被合并到一个报文段里发出（Nagle 算法会加剧这一点），或者一个大消息被拆成多段，接收方从缓冲区读数据时就无法判断消息的分界。

解决办法在应用层自己定义边界，常见三种：一是固定长度的消息；二是用特殊分隔符，比如 HTTP 的头部用回车换行分隔；三是在消息头里加长度字段，也就是 TLV 格式，先读固定长度的头拿到长度，再按长度读体，这是最常用的方案。

UDP 不存在粘包问题，因为它是面向报文的，保留了消息边界。"

### Q5.11 TCP 首部有哪些重要字段？★★

**【面试怎么答】** "重点记这几个：源端口和目的端口各 16 位；序号，标识本报文段第一个字节在字节流中的编号；确认号，表示期望收到对方下一个字节的序号；数据偏移，指出首部长度；窗口字段，用于流量控制，告诉对方自己的接收窗口；校验和；还有六个标志位，其中 SYN 用于建立连接、ACK 表示确认号有效、FIN 表示释放连接、RST 表示强制复位连接、PSH 表示尽快交付上层、URG 表示有紧急数据。"

### Q5.12 SYN Flood 攻击和防御？★★

**【面试怎么答】** "攻击者伪造大量源 IP 发送 SYN 报文，服务端收到后回复 SYN+ACK 并在半连接队列里为每个连接分配资源，但因为源 IP 是伪造的，第三次握手的 ACK 永远不会到来。这些半连接会占满队列，导致正常用户无法建立连接，属于拒绝服务攻击。

防御手段包括：缩短 SYN 超时时间、限制单 IP 的连接速率、增大半连接队列，以及最典型的 SYN Cookie。SYN Cookie 的思路是服务端在第二次握手时不分配资源，而是把连接信息通过哈希编码进初始序号里发出去，只有当第三次握手的 ACK 带着合法的序号回来时才真正建立连接和分配资源。"

### Q5.13 长连接和短连接？★★

**【面试怎么答】** "短连接是每次请求都建立一次 TCP 连接，用完就关；长连接是建立一次连接后复用，连续发多个请求。

长连接的好处是省掉了反复三次握手四次挥手的开销，也避免了每次都要重新经历慢开始阶段。代价是服务端要维持连接状态，占用文件描述符和内存，所以通常配合超时时间和最大请求数来回收空闲连接。

HTTP/1.1 默认使用长连接，通过 Connection: keep-alive 控制。"

## 第 6 章 应用层

### Q6.1 DNS 解析的过程？★★★

**【面试怎么答】** "整体是一个自顶向下逐级查询的过程。

客户端先查本地：浏览器缓存、操作系统缓存、hosts 文件。都没有就向本地域名服务器发起查询，这个通常是运营商提供的或者你配置的公共 DNS。

本地域名服务器如果没有缓存，就依次去问根域名服务器、顶级域名服务器、权威域名服务器。比如查 www.example.com，根服务器告诉它去问 com 的顶级服务器，顶级服务器告诉它去问 example.com 的权威服务器，权威服务器返回最终的 IP。

这里有两种查询方式：主机到本地域名服务器一般是递归查询，本地服务器必须给出最终答案；本地域名服务器到各级服务器一般是迭代查询，对方只告诉它下一步该问谁。

结果会被逐级缓存，缓存时间由 TTL 控制。DNS 默认使用 UDP 的 53 端口，因为查询报文小、要求响应快；当响应超过 512 字节或者做区域传送时改用 TCP。"

### Q6.2 从输入 URL 到页面显示，发生了什么？★★★（最高频综合题）

**【面试怎么答】** "我按顺序说：

第一步，URL 解析。浏览器判断输入的是搜索词还是网址，补全协议，做必要的编码。

第二步，DNS 解析。依次查浏览器缓存、系统缓存、hosts、本地 DNS 服务器，必要时递归到根、顶级、权威域名服务器，拿到目标 IP。

第三步，建立 TCP 连接。客户端和服务器三次握手。这中间涉及底层的处理：主机判断目标 IP 是否和自己同网段，不同网段就把数据发给默认网关，用 ARP 拿到网关的 MAC 地址；数据在中途经过多个路由器逐跳转发，出口处可能经过 NAT 做地址转换。

第四步，如果是 HTTPS，还要进行 TLS 握手，协商加密套件、验证服务器证书、生成会话密钥。

第五步，发送 HTTP 请求。包含请求行、请求头、请求体。

第六步，服务器处理并返回响应，包含状态码、响应头和响应体。中间可能经过 CDN、反向代理、负载均衡。

第七步，浏览器渲染。解析 HTML 构建 DOM 树，解析 CSS 构建样式规则，合成渲染树，布局，绘制。遇到 JS、图片、CSS 等资源会再发起请求。

第八步，连接关闭。HTTP/1.1 默认长连接，会保持一段时间再四次挥手关闭。

这道题的好处是几乎串起了整个网络协议栈，从应用层的 DNS 和 HTTP，到传输层的 TCP，到网络层的 IP 路由，再到链路层的 ARP。"

### Q6.3 HTTP 和 HTTPS 的区别？★★★

**【面试怎么答】** "HTTP 是明文传输的，数据在链路上可以被窃听和篡改，也无法验证对方身份。HTTPS 在 HTTP 和 TCP 之间加了一层 TLS/SSL，提供三个保障：加密防窃听、消息认证码防篡改、数字证书防冒充。

具体区别：端口上 HTTP 是 80，HTTPS 是 443；HTTPS 需要向 CA 申请证书，通常有成本；HTTPS 因为多了握手和加解密，性能开销略高，但现在硬件加速和 TLS1.3 已经把这个差距压得很小了。"

### Q6.4 HTTPS 的握手过程？★★★

**【通俗讲解】** 两个陌生人要说悄悄话。先互相打招呼，各报一串随机数，商量好用哪种暗号规则。服务端出示身份证（证书），客户端拿权威机构的公章去核验。核验通过后，客户端再想一串随机数，用服务端身份证上的公钥锁起来发过去——只有服务端能解开。这样双方就都有了三串随机数，各自算出同一把对称密钥，之后就用这把快锁通信。

**【面试怎么答】** "以 TLS1.2 为例：

第一步，客户端发 ClientHello，携带支持的 TLS 版本、加密套件列表和一个随机数。

第二步，服务端回 ServerHello，选定版本和加密套件，带上第二个随机数，同时把自己的数字证书发过来。

第三步，客户端验证证书：检查签发机构是否受信任、证书是否在有效期内、域名是否匹配、是否被吊销。验证通过后生成第三个随机数（pre-master secret），用证书里的公钥加密后发给服务端。

第四步，服务端用私钥解出这个随机数。此时双方都有三个随机数，各自用相同算法推导出会话密钥。

第五步，双方互发 Finished 报文验证握手完整性，之后改用对称加密通信。

设计上的关键点是：非对称加密只用来安全地交换对称密钥，因为非对称加密慢；实际数据传输用对称加密，因为快。这是两者的结合。

TLS1.3 做了简化，把握手压缩到一个往返，并且默认使用前向安全的密钥交换方式。"

**追问：为什么需要 CA 证书？** "如果只用公钥不用证书，中间人可以把自己的公钥冒充成服务器的公钥发给客户端，客户端无法分辨。证书的作用是让权威第三方 CA 用自己的私钥给'某公钥属于某域名'这个声明签名，客户端用操作系统或浏览器内置的 CA 公钥验签，从而确认公钥的归属。"

### Q6.5 HTTP 各版本的演进？★★★

**【面试怎么答】** "HTTP/1.0 每次请求都要新建 TCP 连接，开销很大。

HTTP/1.1 引入默认长连接、管道化、Host 头支持虚拟主机、Range 支持断点续传、增加缓存控制字段。但它的核心问题是队头阻塞：同一个连接上的请求必须按顺序返回响应，前面的慢了后面全部卡住。浏览器只好靠开多个 TCP 连接来缓解。

HTTP/2 的改进主要有四点：一是二进制分帧，把报文拆成帧传输；二是多路复用，同一个连接上多个请求的帧可以交错传输，解决了 HTTP 层面的队头阻塞；三是头部压缩，用 HPACK 算法和静态表动态表大幅减少重复的头部开销；四是服务器推送。但它底层还是 TCP，一旦某个 TCP 段丢了，整个连接上所有流都要等待重传，这是 TCP 层面的队头阻塞，HTTP/2 解决不了。

HTTP/3 把传输层换成了基于 UDP 的 QUIC 协议，在 UDP 之上自己实现了可靠传输和流控。因为每个流独立，一个流丢包不影响其他流，彻底解决了队头阻塞。另外 QUIC 把 TLS 握手和连接握手合并，首次连接只要一个往返，重连可以零往返；还支持连接迁移，用连接 ID 而不是四元组标识连接，手机从 WiFi 切到 4G 时连接不中断。"

### Q6.6 GET 和 POST 的区别？★★★

**【面试怎么答】** "从规范语义上说，GET 用于获取资源，应该是安全且幂等的；POST 用于提交数据，会改变服务器状态，不幂等。

从表现上说：GET 的参数放在 URL 的查询字符串里，POST 放在请求体里；URL 长度受浏览器和服务器限制，所以 GET 传的数据量小；GET 请求可以被缓存、被收藏为书签、会留在浏览器历史和服务器日志里，所以不适合传敏感信息。

但我想强调一点，这些区别本质上是 HTTP 规范和浏览器实现的约定，不是底层机制的差异。两者底层都是 TCP，GET 也可以带请求体，只是不推荐。所谓 POST 更安全也只是相对的，明文传输一样能被抓包，真正的安全要靠 HTTPS。"

### Q6.7 常见的 HTTP 状态码？★★★

**【面试怎么答】** "按类别记：

1xx 是信息性的，比如 101 切换协议，WebSocket 升级时用。 2xx 成功，200 OK 最常见，204 No Content 表示成功但无返回体，206 Partial Content 用于断点续传。 3xx 重定向，301 永久重定向，搜索引擎会更新索引；302 临时重定向；304 Not Modified 表示资源没变，可以用缓存。 4xx 客户端错误，400 请求语法错误，401 未认证，403 已认证但无权限，404 资源不存在，429 请求过于频繁。 5xx 服务端错误，500 内部错误，502 网关收到无效响应，503 服务不可用通常是过载或维护，504 网关超时。

面试里容易混的两组：401 是你没登录，403 是你登录了但没资格；502 是上游服务器返回了错误响应，504 是上游服务器根本没响应。"

### Q6.8 Cookie 和 Session 的区别？★★★

**【面试怎么答】** "根本原因是 HTTP 是无状态协议，服务器不记得你上次是谁，所以需要额外机制维持会话状态。

Cookie 存在客户端浏览器，服务器通过 Set-Cookie 响应头下发，浏览器之后每次请求自动带上。因为在客户端，所以可以被篡改，不适合存敏感信息，而且有大小限制，通常几 KB。

Session 存在服务端，服务端为每个用户生成一个 SessionID 和对应的数据。SessionID 通常通过 Cookie 传给客户端，所以两者常配合使用。Session 更安全，但服务端要存储，在分布式部署时还需要解决共享问题，常用方案是把 Session 放到 Redis 里，或者干脆改用 Token 方案比如 JWT，把状态放回客户端并用签名保证不被篡改。"

### Q6.9 HTTP 缓存机制？★★

**【面试怎么答】** "分强缓存和协商缓存两级。

强缓存不需要发请求，浏览器直接用本地副本。控制字段是 Cache-Control 的 max-age，或者旧的 Expires，前者优先级更高。

强缓存过期后走协商缓存，浏览器带上标识去问服务器资源变没变。有两组字段：一组是 Last-Modified 和 If-Modified-Since，基于修改时间，精度只到秒；另一组是 ETag 和 If-None-Match，基于内容的哈希，更精确。服务器判断没变就返回 304，浏览器继续用缓存；变了就返回 200 和新内容。"

### Q6.10 常见协议的端口号？★★

**【面试怎么答】** "HTTP 是 80，HTTPS 是 443，DNS 是 53，FTP 用 21 控制、20 传数据，SSH 是 22，Telnet 是 23，SMTP 是 25，POP3 是 110，DHCP 是服务端 67、客户端 68，MySQL 通常 3306，Redis 通常 6379。"

### Q6.11 DHCP 的作用？★

**【面试怎么答】** "DHCP 让主机接入网络时自动获取 IP 地址、子网掩码、默认网关和 DNS 服务器地址，不用手动配置。过程是四步广播交互：客户端广播 Discover 寻找服务器，服务器回 Offer 提供地址，客户端广播 Request 表示接受某一个，服务器回 ACK 确认。地址是租约制的，到期前要续租。它基于 UDP。"

## 第 7 章 网络安全（结合你的研究方向，很可能被问）

### Q7.1 对称加密和非对称加密？★★★

**【面试怎么答】** "对称加密加解密用同一把密钥，代表算法是 AES，速度快、适合大数据量，问题是密钥怎么安全地传给对方。

非对称加密有公钥和私钥一对，公钥加密私钥解密，代表算法是 RSA 和 ECC。它解决了密钥分发问题，但计算开销大，不适合加密大量数据。

实际系统通常结合两者：用非对称加密安全地协商出一个对称密钥，再用对称密钥加密实际数据，HTTPS 就是典型例子。"

### Q7.2 数字签名和数字证书？★★

**【面试怎么答】** "数字签名是用私钥对数据的哈希值加密，接收方用公钥解密并对比哈希，可以同时验证数据完整性和发送者身份，而且发送方无法抵赖。注意签名用的是私钥加密公钥验证，和加密时的方向相反。

数字证书解决的是公钥可信问题。CA 用自己的私钥给'某公钥属于某实体'这个信息签名，形成证书。客户端预置了受信任 CA 的公钥，可以验证证书的签名，从而确认公钥的真实归属，防止中间人替换公钥。"

### Q7.3 常见的网络攻击？★★

**【面试怎么答】** "按层次说几个典型的：

链路层有 ARP 欺骗，伪造 ARP 响应把流量引到自己这里做中间人。 传输层有 SYN Flood，占满半连接队列造成拒绝服务；还有 TCP 会话劫持。 应用层有 DNS 劫持和 DNS 缓存投毒，把域名解析到恶意 IP；有 XSS 跨站脚本，注入脚本窃取用户 Cookie；有 CSRF 跨站请求伪造，利用浏览器自动携带 Cookie 的特性冒用用户身份发请求；有 SQL 注入。

以及大规模的 DDoS，用僵尸网络发起流量洪泛。"

### Q7.4 XSS 和 CSRF 的区别？★★

**【面试怎么答】** "XSS 是攻击者往页面注入恶意脚本，在受害者浏览器中执行，可以窃取 Cookie、篡改页面。防御靠输入过滤、输出转义，以及给 Cookie 设置 HttpOnly 属性让脚本读不到。

CSRF 不需要注入脚本，它是诱导已登录用户访问恶意页面，由这个页面发起一个指向目标站点的请求，浏览器会自动带上目标站点的 Cookie，服务器就误以为是用户本人操作。防御靠校验 Referer、使用一次性的 CSRF Token、设置 Cookie 的 SameSite 属性。

一句话概括：XSS 是盗用你的身份在你的浏览器里为所欲为，CSRF 是借用你的身份骗服务器。"

### Q7.5 防火墙和入侵检测？★

**【面试怎么答】** "防火墙部署在网络边界，按预设规则过滤流量。分组过滤防火墙工作在网络层和传输层，根据五元组做规则匹配，效率高但粒度粗；应用网关或代理防火墙工作在应用层，能理解协议内容，粒度细但开销大。

防火墙是被动防御，只能挡住不符合规则的流量。入侵检测系统 IDS 是主动的，通过特征匹配或异常检测发现可疑行为并告警，通常部署在防火墙之后。"

## 第 8 章 高频综合题与场景题

### Q8.1 网页打不开，你怎么排查？★★★

**【面试怎么答】** "我会按协议栈从下往上排查：

先看物理连接和本机网络配置，用 ipconfig 或 ifconfig 看是否拿到了 IP 和网关。 然后 ping 网关，确认局域网内通不通。 再 ping 一个公网 IP，比如 8.8.8.8，确认能不能出网。如果 IP 通但域名不通，问题就在 DNS，可以用 nslookup 或 dig 验证。 如果 DNS 正常，用 telnet 或 curl 测试目标的 80/443 端口是否可达，排除防火墙拦截。 再往上就是看 HTTP 层的返回，状态码是 4xx 还是 5xx，分别对应客户端问题和服务端问题。 必要时用 traceroute 看路径在哪一跳断了，用抓包工具看具体的握手和请求过程。"

### Q8.2 TCP 为什么可靠而 UDP 不可靠，能不能让 UDP 可靠？★★

**【面试怎么答】** "可以，思路是在应用层实现 TCP 那套机制：给数据编序号、加确认应答、超时重传、滑动窗口和拥塞控制。

实际上已经有成熟方案了，QUIC 就是在 UDP 之上实现可靠传输的代表，HTTP/3 用的就是它。这样做的好处是绕开了操作系统内核里僵化的 TCP 实现，可以在用户态灵活地迭代拥塞控制算法，也解决了 TCP 的队头阻塞问题。

游戏和音视频领域也常见自研的可靠 UDP，因为它们需要对可靠性做精细取舍，比如关键帧要保证送达、普通帧可以丢。"

### Q8.3 一台服务器最多能支持多少个 TCP 连接？★★

**【面试怎么答】** "常见的误区是认为受限于 65535 个端口。实际上 TCP 连接由四元组唯一标识，也就是源 IP、源端口、目的 IP、目的端口。对服务器来说，它自己的 IP 和端口是固定的，变化的是客户端的 IP 和端口，所以理论上限非常大。

真正的限制来自资源：一是文件描述符数量，每个连接占一个 fd，受系统和进程限制；二是内存，每个连接的收发缓冲区都要占内存；三是 CPU 和带宽。

65535 的限制对客户端有意义：单个客户端向同一个服务端 IP 和端口发起连接时，受本地可用端口数限制。"

### Q8.4 你了解 CDN 吗？★

**【面试怎么答】** "CDN 是内容分发网络，把静态资源缓存到离用户更近的边缘节点，减少回源和跨网传输的延迟。

工作方式主要靠 DNS 调度：用户查询域名时，CDN 的 DNS 服务器根据用户的地理位置和节点负载，返回一个最优边缘节点的 IP。边缘节点有缓存就直接返回，没有就回源站取。

好处是降低时延、减轻源站压力、抗一定程度的流量攻击。"

### Q8.5 正向代理和反向代理？★★

**【面试怎么答】** "正向代理站在客户端一侧，客户端知道自己在用代理，服务端不知道真实客户端是谁，典型用途是翻墙、隐藏客户端身份、做统一出口和缓存。

反向代理站在服务端一侧，客户端以为自己直接访问的就是目标服务器，实际上是代理再转发给后端。典型用途是负载均衡、隐藏后端架构、SSL 卸载、缓存加速，Nginx 是最常见的实现。

一句话：正向代理代理客户端，反向代理代理服务端。"
