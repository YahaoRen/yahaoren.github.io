Value-Hijacking: Data Selectors as Poisoning Amplifiers

把数据选择器视为独立安全边界：它不仅决定训练效率，也可能改变恶意样本进入微调集的概率。

Abstract in plain language许多微调流程会先用数据选择器从候选池中挑出“高价值”样本。Value-Hijacking 研究考察一个安全问题：如果攻击者知道选择器偏好，能否构造更容易被选中的恶意记录，使选择阶段反而放大投毒风险？本页只概述已公开 Artifact，不将投稿状态表述为发表结论。

研究问题

大模型指令微调经常面对一个现实限制：候选数据很多，但计算预算有限。数据选择器因此承担了重要角色——它们对样本评分、排序，再把有限预算集中在看起来更有用的数据上。

这带来一个容易被忽略的问题：选择规则不是被动过滤器。当数据供应方具有对抗性、并且能够推断选择器偏好时，样本的“高分”与“安全”并不是同一个概念。

研究关注的不是“选择器是否提高平均效用”，而是“在对抗性数据供应环境中，效用信号是否会被重新利用”。

为什么关注选择阶段

传统训练数据安全分析往往关注投毒比例、训练过程或最终行为。select-then-train 管线在这些环节之前增加了一次有方向性的采样：数据不是随机进入训练集，而是由评分函数决定。

  1. 候选数据供应：来自多个来源的指令样本进入候选池。
  2. 效用评分与排序：选择器根据难度、质量、影响或代表性等信号排序。
  3. 预算内选取：排名靠前的记录进入有限的微调集合。
  4. 训练与评估：模型行为反映被选数据，而不仅是原始候选池的分布。

因此，即使候选池中的恶意样本比例很低，只要它们更符合选择器的偏好，实际进入训练集的占比也可能发生结构性变化。这正是“amplifier”这一表述的含义。

公开 Artifact 包含什么

公开仓库的目标是支持结果检查，而不是提供不受约束的攻击工具。发布内容包含经过清理的参考模块、配置模板、提示模板、论文表格对应的聚合结果，以及轻量验证脚本。

  • src/vhp_artifact/：选择器评分、生成与重排、训练命令构造、推理评估和表格复算的参考模块。
  • results/ 与 derived_tables/：聚合结果及其 Markdown / LaTeX 表格渲染。
  • configs/ 与 prompts/：实验配置和审查协议模板。
  • REVIEWER_GUIDE.md：面向复核者的最短检查路径。

复现边界

一个可信 Artifact 需要同时说明“提供了什么”与“没有提供什么”。仓库中的轻量测试可以复算已发布聚合数据对应的表格、重建统计并检查代码路径，但完整重训练仍需要外部模型权重、数据集、GPU 和 API 访问。

这种边界并不意味着复现失败，而是把验证问题拆成不同层级：第三方可以先确认表格和统计的一致性，再决定是否投入资源执行完整实验。
